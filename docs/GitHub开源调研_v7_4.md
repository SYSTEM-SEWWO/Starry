## 二、从样本里读出的五条趋势

1. **MCP 已成为工具生态的事实标准。**
   Claude Desktop、OpenClaw、Continue、Jini、Moonwalker 均已支持。MCP 的价值
   是把「工具供给」从应用里解耦出去——第三方写一次服务器，所有客户端都能用。
   谁不支持 MCP，谁的工具箱就只能靠自己慢慢堆。

2. **屏幕感知（Screen-aware）是新秀的统一入口。**
   Moonwalker / Jini / Cluely / Highlight 的共同交互是「我看见屏幕上有个东西，
   但我看不懂」→ 一键抓屏 → 就地提问。它把「截图」从**素材准备**升级为
   **问题本身**，省掉了「先框选、再想问什么」两步。

3. **玻璃拟态（Glassmorphism）从加分项变成及格线。**
   上表里几乎每个 2026 年的新项目都把毛玻璃写进 feature 列表。星语 v7.3 的
   真·毛玻璃正好踩在这条线上，不再是差异化，而是不掉队。

4. **语音正在本地化**：本地 whisper + 唤醒词（TARS / DesktopAI / airi）。
   这是趋势，但**依赖体积大**（模型文件百 MB 级）。

5. **动作护栏被认真对待**：Jini 在每次点击/输入/打开应用前弹 YES/NO 卡，
   并在 Rust 侧强制拦截危险路径。这是"agent 能动手"之后的必然配套。

## 三、星语的能力缺口与补齐决策

| 能力 | 星语 v7.3 状态 | 决策 | 理由 |
| --- | --- | --- | --- |
| **MCP 工具接入** | ❌ 无 | ✅ **本轮补齐** | 趋势 1；纯标准库可实现，零新依赖；工具生态外置，长期收益最大 |
| **一键看屏幕问答** | ⚠️ 仅有框选截图 | ✅ **本轮补齐** | 趋势 2；复用既有截图/附件链路，成本极低而体验跃迁明显 |
| 玻璃质感 UI | ✅ v7.3 真·毛玻璃 | 保持 | 趋势 3，已达及格线 |
| 本地语音唤醒 | ❌ 无 | ⏸ **本轮不做** | 趋势 4 成立，但需 whisper/porcupine 等百 MB 级依赖，与 v7.2 确立的轻量化方针正面冲突；记为观察项 |
| 动作护栏 | ⚠️ 内置 12 工具多为只读 | ⏸ **部分不做** | 趋势 5 重要，但星语工具目前不执行系统写操作；MCP 接入后外部工具可写，护栏**下轮必须补** |

### 为什么语音没做（一个诚实的取舍）

TARS 的本地 whisper、DesktopAI 的 Porcupine 都要引入模型文件与原生依赖。
星语 v7.2 刚把打包体积从"全家桶"压到 **134MB**、并排除 15 个未用 Qt 模块。
为一个语音入口把体积再抬上去，等于用**全体用户的启动成本**换**部分用户的
便利**。因此本轮明确不做，并在文档里留痕——这是取舍，不是遗漏。

## 四、本轮落地清单（调研 → 代码 → 自测）

| 补齐项 | 代码 | 入口 | 自测 |
| --- | --- | --- | --- |
| MCP 客户端（stdio JSON-RPC） | `core/mcp.py` | 设置 →「MCP 工具」页：增删改 / 启用 / 测试连接 | 26 项（含端到端） |
| MCP 工具并入智能体 | `McpManager.register_tools()` | 智能体工具箱自动出现 `mcp_*` 工具 | 注册/执行/卸载还原 |
| 一键看屏幕问答 | `core/screen.py`（纯逻辑）+ `app/screenshot_controller.py`（抓屏） | 命令面板「👁 看屏幕问答」+ 4 条预设 | 9 项纯逻辑 |
| 退出清理 | `AssistantApp.quit()` | 断开 MCP 子进程并卸载工具 | 覆盖 |

### 关键实现约束（延续轻量方针）

- **不引入 `mcp` / `anyio` 官方 SDK**：用 `subprocess + json + threading` 实现
  stdio 传输的 JSON-RPC 2.0（newline-delimited），依赖树零增长。
- **启动零开销**：`mcp_servers` 默认为空数组，未配置时完全不触发连接；
  已配置则延迟 1.2s 后在后台线程握手，主线程轮询收尾，不阻塞启动。
- **异常一律收敛为字符串**：MCP 进程崩溃、超时、协议错误都变成模型可读的
  文本结果，绝不把异常抛进智能体循环。

## 五、调研带来的两个额外认知

1. **"工具生态"比"工具数量"重要。**
   星语原本以「12 个内置工具」为卖点，但对照 OpenClaw（技能注册表）与 MCP
   生态后看得很清楚：内置工具再多也是**常数**，接上 MCP 之后才是**变量**。
   本轮补齐的本质，是把工具箱从常数改成变量。

2. **差异化不在"功能更多"，而在"组合独占"。**
   Cherry Studio / Jan / AnythingLLM 各自功能面都比星语宽，但
   「桌面悬浮伙伴 + 网页版免 Key + 网关观测 + 多专家会诊 + 现在再加 MCP」
   这个组合在检索范围内没有第二个项目同时具备。补齐 MCP 之后，这个组合的
   不可替代性进一步增强。
