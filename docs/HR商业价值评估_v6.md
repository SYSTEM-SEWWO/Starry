# HR 商业价值评估 · 星语 Starry v6.0（第四轮评审）

> 评估人：HRBP（产品商业化顾问视角）
> 评估对象：v6.0 —— 网页版接入（浏览器 harness）/ 网关仪表盘 / 液态玻璃组件库 / 450 项自测
> 评估日期：2026-10-23
> 评估基线：HR 复审 v5.1（RC）后的大版本演进

---

## 一、总体判断

v6 是五个版本里**商业叙事最完整**的一个：v5 解决了「个人能用」，v6 开始解决「**别人为什么选你**」。

三个卖点都踩在了真实痛点上：
1. **网页版接入**——「不申请 Key 就能用 DeepSeek 网页版的全部能力」是对免费额度用户的精准打击，零迁移成本；
2. **网关仪表盘**——多服务商用户的运维痛点被产品化，这是从「工具」迈向「平台」的信号；
3. **液态玻璃**——视觉溢价，截图即可传播。

但在模拟新用户完整走查三遍之后，我发现 **v6 的第一次启动体验存在断点**，且有两个「程序员觉得不是问题、用户会觉得是问题」的细节。按商业影响排序如下。

---

## 二、问题清单（按优先级）

### P0-1 网页版「一键就绪」差最后一步：能检测、能引导，但不能代劳

**现象**：新用户按 README 执行 `pip install playwright`，然后在设置 → 网页接入页看到「✗ 未就绪：未安装 Playwright」→ 装好 playwright → 再看到就绪文案里写着「然后执行 playwright install chromium」——**又要去翻终端**。这一步足以流失 30% 以上的意向用户：我们的目标用户是「不想折腾的人」，而这一步恰好是最折腾的一步。

**HR 意见**：设置页「网页接入」页需要**「一键安装浏览器内核」按钮**——点击后在产品内执行 `python -m playwright install chromium`，实时把安装输出显示在状态行。检测 → 引导 → 代劳，三步都要在产品内闭环。这是 P0：它卡在 v6 头号卖点的入口。

### P1-1 健康检查的最坏情况是「假死」：18 家 × 6 秒 = 108 秒无反馈

**现象**：网关仪表盘点「🩺 健康检查」后，按钮变「检查中…」然后**长时间没有任何进度**。串行检查 18 家服务商、每家超时 6 秒，全部超时的最坏情况是 108 秒——用户会以为程序卡死，然后kill进程。

**HR 意见**：两个都要改：① 按钮/状态显示**进度**（「检查中 5/18」）；② 单家超时降到 4 秒、本地服务商快速跳过。健康检查是「给用户信心」的功能，不能自己先制造焦虑。

### P1-2 网关仪表盘里，「DeepSeek 网页版」卡片显示「0 个 Key」——像个没配置的半残通道

**现象**：网页版是 v6 头号卖点，但在仪表盘里它的卡片显示「今日 x 次 · 均延 x · **0 个 Key**」——「0 个 Key」暗示「此通道未配置」，与「完全就绪的免费通道」的事实相反。新用户会困惑：我是不是漏配了什么？

**HR 意见**：网页版卡片的副标题应改为「浏览器接入 · 登录态持久化」，健康检查对它的状态灯用专门的「浏览器」语义。**卖点功能的 UI 呈现不能自己拆自己的台。**

### P2-1 打包后网页版功能不可用，且用户无从得知

**现象**：PyInstaller onefile 包里 playwright 的 node driver（368 个文件）不会自动收集；即使收集了，浏览器内核（~150MB）也不在包里。结果：安装包用户点网页版 → 「未安装 Playwright」→ 但 README 说「网页版接入」是 v6 功能——**货不对板**。

**HR 意见**：spec 里尽量收集 playwright driver（能收多少收多少），README 明确写「安装包默认不含网页版运行时，需要时按设置页指引一键安装」。同时设置页状态行要说清楚「安装包版本」与「源码版本」的差异。

### P2-2 切到网页版时缺少「前置条件检查」，错误要等到第一次提问才暴露

**现象**：用户在模型下拉框直接选「DeepSeek 网页版」→ 提问 → 弹窗「未安装 Playwright」。错误暴露太晚：切换的那一刻就该告诉用户「此模式需要 playwright，设置页可一键安装」。

**HR 意见**：切换到 web provider 时立即探测环境，未就绪则明确提示（但仍允许切换，设置页有修复入口）——**错误要尽早、修复要就近**。

## 三、HR 特别欣赏的部分（保留）

- 网关统计的**旁路设计**（绝不拦截主链路）：这是有架构品味的选择，避免了「监控功能把主干搞挂」的经典事故；
- 网页版「前情提要」发送策略：承认了网页版单轮无上下文 API 的现实，用纯文本拼接解决，没有假装有上下文；
- 选择器可配置覆盖：站点改版是网页 harness 的宿命，提前把逃生舱装好了；
- 450 项自测里包含 12 项真实浏览器端到端——「测试了自己吹的牛」，这在桌面工具里是稀缺品质。

---

## 四、结论

| 编号 | 优先级 | 结论 |
| --- | --- | --- |
| P0-1 | P0 | 必须修复：设置页一键安装浏览器内核（产品内闭环） |
| P1-1 | P1 | 必须修复：健康检查进度显示 + 超时收紧 |
| P1-2 | P1 | 必须修复：网页版卡片文案与状态语义 |
| P2-1 | P2 | 应当修复：spec 收集 driver + README 明示安装包边界 |
| P2-2 | P2 | 应当修复：切换网页版时前置条件检查 |

**总体结论：有条件通过。** P0-1 修复后 v6.1 可直接进入 RC；其余各项随 v6.1 一并交付。继续执行「程序员响应 → HR 复审」闭环。
