# HR 商业价值评估 · 星语 Starry v7.2（第六轮评审）

> 评估人：HRBP（产品商业化顾问视角）
> 评估对象：v7.2 —— 竞品调研前置 / 划词提问 / 桌面拟人化（漫游+气泡）/ 轻量化 / CI exe 打包
> 评估日期：2026-10-26
> 评估基线：HR 复审 v7.0（GA）+ v7.1 动效与打包（功能增量，未单列评审）

---

## 一、总体判断

这一轮最正确的动作，是**先调研再动手**——`docs/竞品调研_v7_2.md` 把「别人在做什么、
为什么火」写在了功能之前，并明确列出了「不跟」的清单（MCP / 绘画 / 多模型并排 / 300+ 预设）。
这比再多做三个功能更有价值：**克制是产品力的上限**。

三个落地项里，划词提问是「结构性优势」（桌面端独有入口），漫游/气泡是「留存型功能」
（把工具变成伙伴），轻量化是「分发优势」（用户装得下才谈得上用）。

但正因为划词提问触碰了**用户选区**，这一条从功能问题升级成了**信任问题**，按商业影响排序如下。

---

## 二、问题清单（按优先级）

### P0-1 「读取选区」的隐私边界没有在产品内说清楚

**现象**：功能说明只写在 README 里（「只在按热键时读一次」）。但用户按下的瞬间，
看到的是一个窗口里出现了自己刚选中的文字——**第一反应是「它是不是一直在监听我？」**
小红书/知乎上关于「桌面助手偷看剪贴板」的质疑从来不少。这不是法律问题，是**感知问题**：
一次误解就足以让用户卸载。

**HR 意见**：迷你窗内必须有一行常驻、可见的说明：「只在你点下动作时读取一次选区：
不常驻监听、不记录、不上传」。**不能只写在文档里，要写在用户产生疑虑的那块界面上。**
P0：它决定这个功能是「好用」还是「不敢用」。

### P1-1 漫游/气泡默认关闭是对的，但「用户发现不了」

**现象**：漫游默认关闭（不打扰，正确）。但一个默认关闭的功能等于不存在——
命令面板里那一行「开启悬浮球漫游」，普通用户不会主动去找。竞品（Clippy / Desk Pet）
恰恰是靠「它自己在动」形成第一印象的。

**HR 意见**：不要求改成默认开启。要求**在提示语里埋一条引导**（「嫌我溜达太吵？
命令面板里能关掉漫游」的正面版本），让用户在被逗乐的同时知道有这个开关。
**低成本、零打扰的发现性。**

### P1-2 「更轻」需要可核对的证据，而不是形容词

**现象**：CHANGELOG 写了「排除 15 个 Qt 模块」「存储层去重」，但没有给出对比数字；
134MB 的 Linux 单文件是变大了还是变小了？用户无法判断。

**HR 意见**：给出三组可核对数据：① 单文件体积（改前/改后）；② 存储层去重前后行数；
③ 新增功能各自的代码量（证明是「小模块」而非往大文件里堆）。**说不出数字的「轻」都是话术。**

### P2-1 CI 的 Windows exe 仍未真机验证

**现象**：`build-windows` job 写好了、本地 Linux 打包验证通过，但 Windows runner
一次都没跑过。Windows 上最大的不确定性是**中文字体与路径**（`星语Starry.exe`、
`dist\星语Starry-Windows\`）——PowerShell 的编码/路径处理是最常见的翻车点。

**HR 意见**：状态如实标注「已配置，待首次 push 验证」，不要把「本地 Linux 通过」
说成「Windows 可交付」。

### P2-2 竞品调研不能只做一次

**现象**：调研文档质量很高，但如果只存在于 v7.2，三个版本后就过期了。

**HR 意见**：把「能力矩阵」定为**每版更新一次**的例行项（哪怕只改一行），
让对标变成机制而不是一次性作业。

---

## 三、HR 特别欣赏的部分（保留）

- **「不跟清单」**：明确拒绝 MCP / 绘画 / 并排对比 / 300+ 预设，并给出理由——
  这是防臃肿的最有效手段；
- **轻量化的落点选得准**：存储层 4 处重复 → 1 个模块，这种「看不见但真实」的减法，
  比删几个注释有价值；
- **自测稳定性修复**：把「偶发 SIGABRT」当成缺陷修（隔离热键 + 显式退出），
  而不是重跑一次了事——发布质量的可信度就是这么攒出来的；
- **动效仍然克制**：新增漫游/气泡都有明确的「不抢鼠标、自动消失、可关闭」约束。

---

## 四、结论

| 编号 | 优先级 | 结论 |
| --- | --- | --- |
| P0-1 | P0 | 必须修复：迷你窗内常驻隐私说明 |
| P1-1 | P1 | 必须修复：提示语埋入漫游引导 |
| P1-2 | P1 | 必须修复：轻量化给出可核对数据 |
| P2-1 | P2 | 应当修复：CI exe 状态如实标注 |
| P2-2 | P2 | 建议：能力矩阵每版更新 |

**总体结论：有条件通过。** P0-1 是一行文案的事，但没有它，划词提问就是负资产。
P1 两条均为「把话说清楚」。处理完即可 GA，无需新增功能。
