## 二、本轮特别确认的三件事

### 1. 他先去找了"别人做到哪了"，而不是直接开始写

这一轮最值得记的，不是新增了多少代码，而是**顺序改变了**：
先做 GitHub 开源检索（`docs/GitHub开源调研_v7_4.md`），拿到
Moonwalker / Jini / OpenClaw / Cherry Studio / Jan.ai 等一批外部样本，
读出五条趋势，再对照星语列缺口，最后才动代码。

这种"先外后内"的顺序，是资深与初级最稳定的分水岭之一。

### 2. 他敢写"不做清单"，并给出代价论证

语音唤醒是明确的行业趋势（TARS / DesktopAI / airi 都在做），但他**明确不做**，
理由是：本地 whisper / Porcupine 会带来百 MB 级依赖，与 v7.2 刚压到 134MB 的
轻量化方针正面冲突——**用全体用户的启动成本换部分用户的便利，不划算**。

能对着趋势说"不"，且说的是代价而不是偷懒，这是判断力，不是执行力。

### 3. 他把一个"常数"改成了"变量"

星语原本的卖点是「12 个内置工具」——这是常数，再多也只能靠自己堆。
MCP 接入之后，任何第三方写的服务器都能被直接调用，工具箱变成变量。

从 HR 视角看，这是一次**能力结构的升级**，不是功能数量的 +1。

## 四、遗留观察（不阻塞，记录在案）

1. **MCP 工具尚无动作护栏**（资深评审坦白清单第 5 条）。
   外部服务器可能提供写文件/执行命令类工具，本轮注册后智能体可直接调用。
   建议下轮列为**必办项**：接入即意味着攻击面扩大。
2. **仅支持 stdio 传输**，HTTP/SSE 型 MCP 服务器会握手失败（有可读报错，不静默）。
3. **中文工具名折叠**存在极低概率的 id 冲突，未做冲突检测。
4. **Wayland 部分合成器下抓屏可能失效**（已有空图保护，不崩溃但不可用）。

以上均为"已知且写明"，不属于隐瞒。

## 五、结论

**通过。本轮评级：A（独立闭环交付）。**

理由：

- **方法**：外部检索先行，取舍有据，不做清单写明代价。
- **工程**：用 200 行标准库替代一整套异步 SDK，依赖树零增长——成本意识明确。
- **质量**：645 项自测全绿，含真实子进程端到端；新增代码全部落在独立模块，
  未向大文件堆砌。
- **诚实**：五条坦白清单主动暴露边界（传输形态、id 折叠、同步阻塞、
  抓屏受限、缺少护栏），且把最危险的一项标为下轮必办。

需要关注的成长点只有一条：**安全护栏意识要再提前半步**——在"接入外部能力"
的同一轮就把"约束外部能力"一起做掉，而不是留到下一轮。这是从"能独立交付"
走向"能独立负责"的最后一公里。
