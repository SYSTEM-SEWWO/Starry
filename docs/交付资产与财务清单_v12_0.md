## 2. APK 单独核算（按要求单列）

> 用户明确要求「在财务里面把 APK 单独拎出来」。原因是：**它体积最大、
> 构建链最重、需要签名密钥、需要真机验收、发布风险最高**，
> 与 EXE / deb 的成本结构完全不同，不应混在「二进制资产」一行里。

### 2.1 APK 资产明细

| 条目 | v11.5.0（历史） | v12.0.0（本版） |
| --- | --- | --- |
| 文件 | `星语 Starry-11.5.0.apk` | `星语Starry-Android-v12.0.0.apk` |
| 体积 | 51,980,670 字节 | 待产出（同量级，约 50MB） |
| 产出方 | 历史交付 | `.github/workflows/build-android.yml`（CI） |
| 本机可产出 | 否（当时亦有工具链） | **否**，缺 JDK 17 / Android SDK / NDK / Gradle / `apksigner` |
| 签名 | v1 + v2/v3 全有，Signing Block 头尾 4088 自洽 | CI 用仓库 Secret 签名 + `apksigner verify` |
| 静态鉴定 | **21 通过 / 1 失败 / 2 提示**；唯一 FAIL 为 `toga 0.2.15` 与 `toga-core 0.5.7` 混装 | 源码已消除混装；到货需过 `verify_apk.py --strict` |
| 应用代码 | 含 F1–F8 八项缺陷 | F1–F8 全部修复，37 项真实核心集成回归通过 |
| 分发状态 | 仅作历史归档，**不推荐继续使用** | 待 tag 触发产出 |
| 真机验证 | 未验证 | **未验证**（无设备 / 模拟器），不得声称不闪退 |

### 2.2 APK 的成本构成（与其它资产对比）

| 成本项 | APK | EXE | deb |
| --- | --- | --- | --- |
| 工具链 | JDK 17 + Android SDK(API 34) + NDK + Gradle + Python 3.11 + Briefcase + Chaquopy | PyInstaller 6.22.3（pip 一个包） | 纯 Python 标准库（零外部工具） |
| 本机能否构建 | ❌ | ✅ | ✅ |
| 构建耗时 | CI 侧（Gradle 全量编译，通常显著长于另两者） | 本机约 40s（含 clean） | 本机 <1s |
| 签名 / 密钥 | **必须**，v1+v2/v3，需 keystore 与 Secret 管理 | 无（未做代码签名） | 无 |
| 产物体积 | ~50MB | ~16MB | ~172KB |
| 验收门槛 | `apksigner verify` + `verify_apk.py --strict` + 真机清单 | `--version` / `--platform` / 6 项冒烟 | ar / control / data 解析 |
| 依赖锁定 | `toga-core/toga-android 0.5.7` 等全部钉版本 | `starry_cli.spec` hiddenimports | control 声明系统 Python 依赖 |
| 分发带宽权重 | **最高**（约为 EXE 的 3.3 倍、deb 的 300 倍） | 中 | 极低 |
| 主要风险 | 签名失效 / 依赖混装 / 真机闪退 | SmartScreen 未签名提示 | 需系统 python3 |

### 2.3 本版为 APK 付出的专项投入

- **鉴定**：`scripts/verify_apk.py`（静态鉴定器，含 21+ 项检查，工具自身自纠 3 次）

- **测试**：`tests/test_android_v12.py` 37 项 + 修正 `android/test_app_logic.py` 16 项；
- **门禁**：`build-android.yml` 新增 `verify_apk.py --strict`，混装包一律阻断；
- **文档**：`使用指南_Android_APK_v12_0.md`（含 14 项核心功能核对清单）+
  `releases/assets/v12.0.0/apk/README.md`（产出与验收说明）。
