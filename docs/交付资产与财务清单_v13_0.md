### 3.1 为什么单独归集、为什么现在为空

- 用户明确要求「在财务里面把 apk 单独拎出来」，因此从 v12 起 APK 就有独立目录与独立条目，v13 保持。
- 本机为 Windows，缺 JDK 17 / Android SDK / NDK / Gradle / `apksigner`，无法真实编译并签名 APK。
- v11.5 的历史 APK 是**已签名包**；只替换内部 `assets/chaquopy/app.imy`
  会让 v1 摘要与 v2/v3 APK Signing Block 全部失效，得到装不上的包。
- **本版不伪造 APK**。三端同源代码已就绪（`core/` ↔ `android/core/` 44 文件一致），
  签名包由 CI 在推 `v13.0.0` tag 时真实产出，产物命名
  `星语Starry-Android-v13.0.0.apk`。

### 3.2 到货后如何补登记

1. 把 APK 放进 `releases/assets/v13.0.0/apk/`；
2. 跑 `apksigner verify --verbose <APK>` 与
   `python scripts/verify_apk.py --apk <APK> --expect-version 13.0.0 --strict`；
3. 重跑 `update-manifest.yml`（或手动 dispatch 指定 tag），
   它会下载全部 Release 资产、从真实字节计算哈希，
   生成含 `android` 条目的正式 `update.json`；
4. 在本表补登大小与哈希，并重跑 `make_release.py` 刷新快照与 `SHA256SUMS`。

## 6. 成本结论

- **本机新增现金支出：0**（无付费 API、无云构建、无新依赖、无签名证书）。
- **新增分发体积**：EXE 15.9 MB + deb 195 KB + 清单 1.2 KB ≈ 16.1 MB；
  源码快照与 zip 的体积见 `MANIFEST.md`。
- **CI 成本**：`update-manifest.yml` 只在 Release published 时运行一次，
  可重跑；不引入常驻服务或定时轮询。
- **待发生成本**：v13 签名 APK 的 CI 构建分钟数与真机验收，由 `build-android.yml` 承担。
