# 代码安全性评估 · V10.0

> 评估对象：V10.0 新增的平台检测（`core/platforms.py`）与无界面命令行引擎
> （`core/cli.py` / `starry_cli.py` / `starry_cli.spec`）。
> 结论：**A-（稳健）**。零新增外部依赖、无新网络面、复用既有安全护栏。

## 1. 攻击面盘点

| 新增面 | 风险 | 处置 |
| --- | --- | --- |
| 命令行参数解析（`argparse`） | 低 | 标准库，无 `eval`/命令拼接 |
| `--config` 读外部 JSON | 中 | 仅 `json.load`，不执行；路径由用户显式给出 |
| 智能体工具执行（`--agent`） | 中 | 复用 V9 既有 `execute_tool`，未新增命令执行面 |
| 网页接入型服务商拒绝 | — | `is_web_site` 显式拦截，避免 CLI 误用浏览器 harness |
| 平台检测读 `/etc/os-release` | 低 | 只读、异常兜底为空串（`core/platforms.py:18`） |

## 2. 关键安全证据

- **零 PyQt 依赖 → 缩小攻击面**：`core/cli.py` 仅导入纯逻辑模块，不引入浏览器/Qt 网络栈；
  验证 `grep -rln PyQt5 core/agent core/cli.py core/platforms.py` 无命中。
- **配置文件权限**：沿用 `AppConfig.save` 的 `0o600`（`core/config.py:394`），
  API Key / 许可密钥不泄露给其他用户。
- **客户端构造护栏**：`build_client` 对网页接入型服务商（`web_deepseek` 等）主动抛错，
  提示改用桌面版（`core/cli.py:29` + 自测「网页接入型服务商在 CLI 被拒绝」）。
- **自测覆盖**：`test_v100_cli_platform` 28 项断言含平台检测、build_client、JSON 输出、
  四端后缀互异（selftest 779 项全绿）。

## 3. 遗留风险与建议

1. **`--agent` 工具执行**：命令行版开放 `--agent` 即复用本地工具（含 `run_command` 类）。
   建议在文档与产品层明确「仅在你信任的运行环境启用」，并沿用 V7.5 的破坏性工具二次确认逻辑。
2. **`--api-key` 命令行泄露**：Key 可能残留在 shell 历史。已在指南中建议优先用配置文件（0o600），
   可在后续版本加 `--api-key-stdin` 从管道读取。
3. **Termux 权限**：Android 形态下工具执行等同 Termux 进程权限，需用户自知。

## 4. 最终评分

- 机密性：A（配置 0o600、无新网络面）
- 完整性：A-（平台检测异常兜底，无注入点）
- 可用性：A（零依赖、跨端可运行）
- **综合：A-**
