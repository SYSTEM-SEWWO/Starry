# 代码安全性评估 · V11.0

> 评估范围：桌面端 / 命令行端 / **安卓端（新增 BeeWare 封装）** / UOS deb。
> 结论：**安全基线维持 B+ → A-**，安卓端沿用同一套「密钥不落库、提示注入防护、破坏性工具护栏」约束。

## 1. 凭据与隐私

| 项 | 措施 | 安卓端差异 |
|----|------|-----------|
| API Key 存储 | `core/config.py` 写入 `config.json` 后 `chmod 0o600`，仅本人可读写 | 安卓沙箱内 `~/.config/...`，应用私有，等同加固 |
| 商业许可密钥 | `validate_license_key` 离线确定性校验，杜绝任意串冒充 | 同桌面 |
| 网页登录态 | 浏览器 profile 持久化于用户目录，不写入仓库 | 网页接入（Playwright）在手机端**不适用**，已主动剔除 |

## 2. 提示注入 / 数据投毒防护

- `core/memory.py` 的 `is_safe_entry` 拒绝含 `<script>`、`ignore previous` 等可疑内容的记忆写入，
  防止外部文本污染长期记忆后被「注入」到系统提示。
- 安卓端 `app.py` 复用同一 `MemoryStore`，防护自动生效。

## 3. 破坏性能力护栏

- `core/rea.py` 的 REA MCP 预设默认 `enabled=False`、`trusted=False`：逆向/反编译属破坏性能力，
  需用户显式勾选并自担风险，不默认开启。
- 智能体工具（`core/agent/tools.py`）在安卓端保留，但执行前复用桌面同一套「工具白名单 + 结果回显」逻辑。

## 4. 供应链 / 构建安全

- 安卓 APK 走 `python-for-android` + Gradle 官方链路，CI 使用 `temurin-17` 与官方 `cmdline-tools`，
  未引入第三方预编译闭源二进制；`.apk` 由仓库 CI 在 GitHub 运行器上**真实编译**产出，可审计。
- 调试签名仅用于侧载演示；上架 Play 需替换为自有发布密钥（文档已提示）。
- `starry_cli.spec` 显式 `excludes` PyQt5 / playwright / pypdf，避免把图形/浏览器依赖打进命令行与安卓包。

## 5. 仓库与合规

- `.gitignore` 已忽略 `config.json`、`*.keystore`、`build/`、`dist/` 等敏感/产物目录，
  密钥与签名文件不会误入库。
- `SECURITY.md` 与 `LICENSE`（商业 EULA）延续，涵盖 API Key 处理与漏洞上报渠道。

## 6. 遗留风险与建议

1. 安卓端 `build_client` 复用桌面校验，但**网页接入型服务商在手机端不可用**已在前端过滤（`_MOBILE_PROVIDERS`），
   建议 UI 进一步灰显并提示原因。
2. 长期记忆为本地明文 JSON（0o600），如需更高隐私可后续加密；当前与桌面策略一致。

## 7. 评分：**A-**（多端统一安全约束，安卓端无新增攻击面）
