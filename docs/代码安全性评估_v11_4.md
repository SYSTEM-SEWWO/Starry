# 代码安全性评估 · v11.4.0

> 评审范围：v11.4.0 电脑端新增功能（消息引用 Quote / 分支对话 Branch）及其 UI 接入。

## 1. 消息引用（新增 `format_quote` / `build_quoted_prompt`）

- 两个核心均为**模块级纯函数**：仅读取 `message["content"]`、拼装字符串，不执行、不落盘外部输入，**无 `eval` / 命令执行 / 路径拼接 / 子进程调用**。
- 引用块把历史消息**原文**注入新 user 消息发给模型，属常规 prompt 组合，未引入文件系统 / 网络能力。
- `QUOTE_MAX_CHARS=300` 截断同时限制上下文膨胀，避免超长回答被整体塞入输入。
- 过滤 `role == "system"` 与空内容，避免系统提示被引用进用户可见气泡。

## 2. 分支对话（新增 `branch_from` / `list_branches`）

- `branch_from` 仅对内存 `messages` 做**浅拷贝 + 切片**（`messages[:index+1]`），写入既有 `sessions.json`，沿用 `core.storage.save_json` 的原子写入与权限收敛，无新落盘面。
- `branched_from` 只存 `{session_id, index}`（本地 id + 整数），**无用户可控路径**，不存在 Zip Slip / 路径穿越。
- `index` 做 `0 <= index < len(msgs)` 校验，负索引 / 越界 / 会话不存在一律返回 `None`，避免越界读写。
- 新会话 id 由 `os.urandom(3).hex()` 生成，与既有 `create()` 一致，无碰撞 / 可预测风险变化。

## 3. UI 接入（`MessagePickerDialog` + 命令面板）

- 消息预览用 `QListWidgetItem` / `setToolTip` 等**安全富文本 API**，不做 HTML 字符串拼接执行，无注入面。
- 追问输入经 `QLineEdit.text()` 取得后仅作为文本传给 `on_send`，不 eval、不拼 shell 命令。
- 打开选择器前先 `_save_current_session()` 对齐索引，属状态一致性保护，无安全副作用。

## 4. 依赖与向后兼容

- 新增逻辑**零新增第三方依赖**，仅用标准库（`json` / `os` / `re` / `time`）；`core` 层不引入任何联网 / 执行类包，安卓与桌面同源复用。
- 新增字段（`branched_from`）全部经 `.get()` 读取，旧 `sessions.json` 无迁移、无解析异常风险。
- `ui/message_picker_dialog.py` 仅依赖已有 PyQt5，未扩大桌面端攻击面。

**结论**：v11.4.0 新增代码面无新增安全风险（纯字符串处理 + 本地内存拷贝 + 安全 Qt 展示），可发版。
