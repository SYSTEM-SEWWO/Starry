# 代码安全性评估 · v11.5.0

**评估范围**：`core/insights.py`（新）、`core/sessions.py::merge_into`、
`core/cli.py::_emit` / `starry_cli.py` 编码兜底、`ui/insight_dialog.py`、
`.github/workflows/build-windows.yml`。

## 1. 纯逻辑层（core/insights.py）

| 检查项 | 结果 |
|---|---|
| 文件写入 / 网络调用 | 无。`diff/merge/stats` 全部为内存计算 |
| 动态执行（`eval`/`exec`/`pickle`） | 无 |
| 入参修改 | 无。返回新对象，单测 `test_merge_no_mutation`、`test_diff_empty_and_no_mutation` 覆盖 |
| 输入清洗 | `message_content` 只取文本字段，多模态非文本部分忽略；`_fingerprint` 做空白规范化 |
| 越界 / 空值 | `merge_into` 拒绝不存在会话与自合并；空会话统计返回全 0，不抛异常 |

**结论**：新增分析层是只读纯函数，攻击面为零。

## 2. Windows 编码兜底（重点复核）

- `starry_cli.py` 的 `reconfigure(errors="replace")` 仅放宽不可编码字符处理，
  **不改变编码、不隐藏错误内容**，对 Linux/macOS 无副作用。
- `core/cli.py::_emit` 只捕获 `UnicodeEncodeError` 一种异常；
  其它 I/O 异常照常向上抛出，**不吞真实故障**。
- 最外层 ASCII 兜底仅作用于打印，不参与业务数据流。
- 三端 `core/cli.py` 字节一致，避免「Windows 修了、Linux 没修」的分叉。

**结论**：修复精准且最小侵入，未引入异常吞噬或信息泄漏。

## 3. 合并操作的数据完整性

- `merge_into` 中 `starred` 下标按 `report["mapping"]` 重映射后
  `sorted(set(...))`，杜绝越界或重复下标（收藏读取处有 `0 <= idx < len(msgs)` 保护）。
- 来源会话**不删除**，保留可回溯；target 只做追加，不覆盖已有消息。
- `tags` 合并去重，不引入外部可控的无限增长（会话上限 `MAX_SESSIONS=50` 仍由 `_trim` 兜底）。

## 4. UI 与工作流

- `InsightDialog._on_save` 写文件前经 `QFileDialog`，捕获 `OSError` 提示用户；
  不写入配置目录、不提权。
- `build-windows.yml` 仅 `contents: write`（发布 Release 所需最小权限）；
  CI 中的密钥仅使用 GitHub 自带 `GITHUB_TOKEN`，未引入新的长期凭据。
- exe 未签名属分发现状（已在指南中提示 SmartScreen），不涉及代码安全缺陷。

## 5. 遗留风险与建议

| 风险 | 等级 | 建议 |
|---|---|---|
| 上架 Play / 正式分发仍用演示 keystore | 中 | 用自有发布密钥替换 `android/starry-release.keystore`（历史沿用建议） |
| exe 无代码签名 | 低 | 正式分发购买代码签名证书 |
| `estimate_tokens` 为估算 | 提示 | 不用于计费，仅作统计参考（已在 API 文档标注） |

## 结论

**通过**。v11.5.0 新增代码无新增安全缺陷；Windows 编码修复在不掩盖异常的前提下
消除了真实崩溃；合并逻辑对下标与来源数据做了完整保护。
