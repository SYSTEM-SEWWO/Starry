# 代码安全性评估 · v13.1.0

> 范围：v13.1 新增的 `core/hub.py`、`ui/hub_dialog.py`、`main.py` 自检入口、
> CLI Hub 参数、`skills/` 示例技能、两个 spec 与 CI 变更。
> 方法：静态审读 + 真实模块调用 + 子进程冒烟；不使用「应该没问题」式结论。

## 1. 结论

| 项 | 结论 |
| --- | --- |
| 远程代码执行 | 未发现。技能正文只作为字符串展示/写入提示词字段，无 `eval` / `exec` / `subprocess` 调用 |
| 自动下载 / 自动安装 | 未发现。`scan_dir` 只遍历本地目录；无 `urllib` / `requests` 出现在 Hub 路径 |
| 敏感信息外泄 | 未发现。Hub 不读密钥、不打印 `config.json` 中的 `api_key` |
| 供应链完整性 | `hub.json` 与 `update.json` 均为 SHA-256 完整性校验，**非签名认证**，已在文档与 UI 明示 |
| 越权写入 | 仅 `--hub-import` / GUI「导入」写 `config.json`，且需用户显式指定技能 ID |
| 发布快照密钥 | `make_release.py` 的 `is_sensitive()` / `assert_no_secrets()` 保持生效 |

## 3. 必须向使用者明示的安全边界

1. **`digest` ≠ 签名**。SHA-256 只能证明「内容没被无意改动」，不能证明「发布者是谁」。
   若攻击者能替换清单本身，就能同时替换摘要。因此 `hub.json` / `update.json`
   必须来自可信 HTTPS、GitHub Releases 或官方仓库，并建议与带外公布的哈希核对。
2. **导入技能等于信任提示词**。Hub 不执行正文，但正文会成为系统提示词的一部分，
   仍可能通过提示注入影响模型行为。请只导入可信任来源的技能。
3. **Hub 不联网**，因此也不会替用户校验远程来源真实性；这一步由使用者负责。

## 4. 本轮修掉的与输入校验相关的问题

| 问题 | 风险 | 处理 |
| --- | --- | --- |
| `_as_list()` 收到 dict 会 `str(dict).split(",")` | 畸形 frontmatter 产生垃圾工具名 | 返回 `[]`，只接受标量 / 列表 |
| 内联 `allowed-tools` 未归一化 | 上层拿到字符串却按列表用 | `_LIST_KEYS` 在 `parse_frontmatter` 层统一归一化 |
| 清单条目 `name` 为空仍被收录 | 生成无效技能 | `validate_hub_manifest` 逐条拒绝 |
| 清单条目 `sha256` 任意长度 | 伪造摘要混入 | 强制 64 位十六进制 |
| `--hub-import` 对只有元数据的技能 | 写入空提示词 | 显式拒绝并提示从原仓库取正文 |
