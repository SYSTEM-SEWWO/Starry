# 代码安全性评估 · 星语 Starry V9.0

> 评估对象：V9.0 相对 V8.0 的新增面（深度思考可视化、REA 逆向工程集成、产物预览）。
> 基线安全机制（EULA 防篡改令牌、License 校验、config.json 0o600、MCP 命令白名单、破坏性工具二次确认）在 V7.5/V8.0 已建立，本次**未退化**。

## 1. 新增攻击面与结论

| 新增模块 | 风险点 | 处置 | 评级 |
|---|---|---|---|
| `core/rea.py`（REA 预设） | REA 属**破坏性逆向能力**（可读取/分析任意本地二进制） | 预设 `enabled=False` 且 `trusted=False` 默认关闭；需用户在设置页显式启用并连接；复用 MCP 现有命令校验与破坏性工具确认（`core/mcp.py` `classify_destructive` / `confirm_cb`） | 低（默认关闭 + 需授权） |
| `app/assistant.py:1103 open_artifacts` | `webbrowser.open("file://"+临时文件)` | 仅对**自身生成**的 ```html 块落地到系统临时目录并打开，不打开任意外部路径；不执行脚本、不写入项目目录 | 低 |
| `ui/floating_ball.py:154 ThinkingCaption` | 思考字幕渲染 LLM 流式文本 | 纯展示控件（`WA_TransparentForMouseEvents`），文本经 `Qt.TextWordWrap` 渲染，**不执行、不_eval、不拼接命令** | 无 |
| 命令面板新增 `rea` / `artifacts` 入口 | 功能可达性 | 均为本地能力，无网络外发（REA 连接由用户配置） | 无 |

## 2. 关键证据

- **REA 默认关闭 + 不信任**：`core/rea.py:25` `REA_MCP_PRESET = {"enabled": False, "trusted": False}`；`ensure_rea_preset` 仅做 name 去重并入（`core/rea.py:90`）。
- **复用 MCP 安全护栏**：REA 经 `core/mcp.py` 既有 `McpManager` 接入，沿用 V7.5 的命令预校验（`shutil.which`）与 V7.5 破坏性工具 gate（`confirm_cb`）。
- **产物预览不越权**：`extract_html_artifact`（`app/assistant.py:56`）仅用正则提取 ```` ```html ```` 块；`open_artifacts`（`app/assistant.py:1103`）写 `tempfile.mkstemp`，路径由系统分配，不接收外部输入。
- **思考字幕无注入面**：`ThinkingCaption.paintEvent` 将文本交给 `QPainter.drawText`，Qt 不解释 HTML/脚本；`show_thinking_text`（`ui/floating_ball.py:337`）仅 `strip()` 后存储展示。

## 3. 配置与数据保护（延续）

- `config.json` 仍 `os.chmod(..., 0o600)`（`core/config.py` `save()`）；`memory.json` 同策略（`core/memory.py`）。
- `.gitignore` 已忽略 `config.json` / `memory.json` / `*.key` / `*.pem` / `secrets.json`。
- 无新增第三方依赖、无新增网络外发端点、无新增权限请求。

## 4. 总体评级

**A-（安全）**：默认最小权限（REA 关闭 + 不信任）、新控件零注入面、复用既有 MCP 护栏；与 V8.0 持平。
建议（非阻断）：REA 启用时可在 UI 增加一次「逆向目标范围」二次确认弹窗，进一步降低误用风险。
