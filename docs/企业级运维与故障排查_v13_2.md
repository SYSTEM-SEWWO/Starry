# 企业级运维与故障排查 · 星语 Starry v13.2.0

> 面向：部署人员 / 管理员 / 支持工程师。
> 目标：把「用户说一开始报 HTTP 401」变成一条 **5 分钟内可闭环**的 SOP。

## 1. HTTP 401 排查 SOP（真实场景）

真实 GUI 测评复现的是：**已填过 Key 但 Key 失效 / 与 Base URL 不匹配**，
启动时自动拉 `/models` 返回 401。v13.2 之后它**不再弹窗打扰**，但仍可完整追溯。

```
用户报告「启动报错 / 模型列表空」
   │
   ├─ 1. Ctrl+K → 「🩺 API 诊断」（或 CLI: starry --hub-diagnostics 看扫描类问题）
   │      看最近一条：分类 / 操作 / HTTP 状态 / 建议
   │
   ├─ 2. 若分类 = auth(401)
   │      设置 → 服务商：核对 API Key 与 Base URL 是否属于同一服务商
   │      · 检查 Key 是否过期 / 被轮换 / 复制时带入空格
   │      · 检查 Base URL 是否误填成网页登录页地址
   │
   ├─ 3. 若分类 = config（未配置）
   │      首次使用：填 Key；或改用「网页大模型」等免 Key 接入
   │
   ├─ 4. 若分类 = network / server / rate_limit
   │      属临时故障，按建议退避重试；无需改配置
   │
   └─ 5. 仍无法解决：点「📋 复制诊断」把脱敏文本发给支持人员
          （不含 Key / Token / 请求体 / 聊天内容，可安全外发）
```

**关键改变**：启动自动刷新失败现在是**静默降级**——只写诊断、不弹 toast；
只有用户在设置里手动点「测试连接 / 获取模型」才显示分类化、可操作的错误卡片。
离线能力（Skills Hub / 整体项目工作台 / 星尘 / 存档）**不受 401 影响**。

## 2. 错误分类速查

| 分类 | 触发 | 是否重试 | 退避 | 主操作 |
| --- | --- | --- | --- | --- |
| `auth` | 401 | 否 | — | 打开设置核对 Key / Base URL |
| `quota` | 402 | 否 | — | 充值或换模型 |
| `forbidden` | 403 | 否 | — | 检查账号权限 |
| `not_found` | 404 | 否 | — | 检查 Base URL / 模型名 |
| `rate_limit` | 429 | 是 | 30s 起 | 稍后重试 |
| `server` | 5xx | 是 | 10s 起 | 自动重试 |
| `network` | 连接失败 / 超时 / DNS | 是 | 5s 起 | 检查网络与代理 |
| `parse` | 非 JSON 响应 | 否 | — | 确认不是网页地址 |
| `config` | 未配置 | 否 | — | 打开设置 |
| `unknown` | 其它 | 是 | 5s 起 | 打开诊断 |

退避公式：`min(300, base × 2^(attempt-1))`，封顶 5 分钟。
连接超时与读取超时分离（默认 `(5s, 15s)`），避免单个长超时卡住启动。

## 3. 部署与配置

### 3.1 数据目录隔离（企业部署 / 便携模式 / 多实例）

```bash
# Windows（PowerShell）
$env:STARRY_DATA_DIR = "D:\StarryProfiles\user01"
.\星语Starry.exe

# Linux
STARRY_DATA_DIR=/srv/starry/profiles/user01 starry --hub-config-show
```

设置后 `get_config_dir()` **直接**使用该目录，不再回退 `%APPDATA%` / `~/.config`。
这是 v13.2 修复的高风险缺陷：此前 Windows 忽略该变量，自动化与多实例会
读写同一份用户真实 `config.json`（含 API Key）。

### 3.2 Hub 配置

统一在 `config.json` 的 `hub` 段；完整 schema、默认值与边界见
`docs/HUB兼容范围与配置_v13_2.md`，示例见项目根 `config.hub.example.json`。

```bash
starry --hub-config /etc/starry/hub.json --hub
starry --hub-config-show          # 核对生效配置
starry --hub-diagnostics          # 核对来源与扫描异常
```

CLI 覆盖项：`--hub-sources github,deepseek`、`--hub-source <目录>`。

### 3.3 审计日志（可选）

```bash
STARRY_API_LOG=/var/log/starry/api.jsonl starry --workbench
```

- JSONL 追加写，每条含时间、分类、操作、HTTP 状态、脱敏摘要；
- **默认关闭**，不设置就不落盘；
- 内容已脱敏，不含 API Key / Bearer Token / 请求体 / 聊天内容；
- `core/apidiag` 内存环形缓冲 100 条，`ui/api_diag_dialog.py` 可查看 / 复制 / 清空。

## 4. 密钥与数据安全

| 项 | 处理 |
| --- | --- |
| `config.json` 权限 | Linux/macOS 保存后 `chmod 600`；Windows 依赖用户目录 ACL |
| 错误信息 | 经 `apierrors.redact()`，移除 `Bearer ...`、`sk-...`、`api_key:`、`token=`、查询串密钥 |
| 上游响应体 | **不再原样展示**，只保留脱敏摘要（≤160 字符） |
| 诊断 / 审计 | 只存结构化分类与脱敏摘要 |
| 发布快照 | `make_release.py` 的 `is_sensitive()` + `assert_no_secrets()` 双重扫描 |
| 历史遗留 | `releases/星语Starry-v11.5.0/` 含 `starry-release.keystore`，**公开分发前必须移除或轮换** |
| 认证强度 | `hub.json` / `update.json` 的 digest 是**完整性校验，不是签名认证**；请从可信 HTTPS / Release 获取 |

## 5. 离线可用性

以下能力**不需要 API Key、不联网**，401 时照常可用：

- Skills Hub（GitHub / DeepSeek / Claude Code / WorkBuddy 技能发现与导入）
- 技能更新判定（`hub.json`）
- 整体项目 / 多线并行 / 工作台
- 程序版本更新判定（`update.json`）
- 星尘卡 / 上下文预算 / `.starry` 存档 / 环境自检
- GUI EXE 的 `--version` / `--selftest --out`

## 7. 已知限制（不粉饰）

1. 本机无 JDK 17 / Android SDK / NDK / Gradle / apksigner，**不产出 v13.2 签名 APK**；
   `releases/assets/v13.2.0/apk/` 仅 README，真机未跑，不能声称实测不闪退。
2. 命令面板在「单击只选中、Enter 不执行、双击才触发」上交互不一致
   （真实 GUI 测评发现，见 `docs/真实GUI测评报告_v13_2.md` P7），**本版未修复**。
3. GUI 自检是 offscreen 装配验证，未做真人交互点击测试；真人测评在源码态完成。
4. frontmatter 解析器是有意限定的 YAML 子集，不支持锚点 / 复杂嵌套。
5. `digest` 非签名认证；如需来源认证建议后续引入 Ed25519 签名。
6. 两个新对话框（Skills Hub / API 诊断）尚未跟随暗色主题。
