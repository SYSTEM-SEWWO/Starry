# 星语 Starry v12.0.0 · 使用指南

> 跨平台本地优先 AI 助手：PyQt5 桌面 / Windows EXE / Linux·UOS deb / CLI / Toga 安卓。
> 本指南覆盖**电脑端**全部用法；安卓单独见 `使用指南_Android_APK_v12_0.md`。

---

## 0. 我该用哪个

| 你的情况 | 用这个 | 入口 |
| --- | --- | --- |
| Windows，要图形界面 | 源码运行桌面版 | `python main.py`（需 `pip install -r requirements.txt`） |
| Windows，只要命令行 / 想直接双击 | `星语Starry-CLI.exe` | `dist/星语Starry-CLI.exe`，免 Python |
| Linux / UOS，命令行 | `星语Starry-CLI-v12.0.0.deb` | `sudo dpkg -i …deb` → `starry --version` |
| 想看完整项目 / 二次开发 | `星语Starry-v12.0.0.zip` | 解压即用，含全部源码与 md 文档 |
| 安卓手机 | 签名 APK | 见 `使用指南_Android_APK_v12_0.md`（由 CI 产出） |

首次使用都需要在「设置」里填自己的 API Key；**不填 Key 也能用本地功能**
（星尘卡、上下文预算、存档、自检），只是不能发起模型对话。

## 1. Windows 桌面 GUI

```bash
pip install -r requirements.txt
python main.py
```

启动流程：`QApplication` → EULA 校验 → 启动画面 → 主窗口（关闭窗口不退出，
托盘常驻）。快捷键 `Ctrl+K` 打开命令面板。

配置文件位置：Windows `%APPDATA%/<APP_ID>/config.json`，
`AppConfig.save()` 会写入，POSIX 下权限 `0o600`（含 API Key）。

## 2. Windows CLI EXE（免 Python）

```bash
dist\星语Starry-CLI.exe --version      # 星语 Starry 12.0.0
dist\星语Starry-CLI.exe --platform
dist\星语Starry-CLI.exe --doctor
```

### 全部 v12.0 新增命令

| 命令 | 作用 | 示例 |
| --- | --- | --- |
| `--doctor` | 运行环境 / 版本一致性自检：版本、平台、配置目录、依赖状态、三端同源 | `starry --doctor` |
| `--budget N` | 对当前会话给出 token 上限 N 的上下文裁剪计划（只给计划，不改数据） | `starry --budget 800` |
| `--archive PATH` | 把全部会话 + 长期记忆导出为 `.starry` 存档 | `starry --archive backup.starry` |
| `--restore PATH` | 从 `.starry` 导入；校验失败一律拒绝；覆盖前自动备份 | `starry --restore backup.starry` |
| `--echo` | 对话结束后附加打印一张本地生成的星尘卡（零 token、零联网） | `starry --echo --ask "你好"` |

原有 `--chat` / `--agent` / `--ask` / `--version` / `--platform` 等保持不变。

**实测**：`--version` / `--platform` / `--doctor` / `--budget 800` /
`--archive` / `--restore` 六项退出码全为 `0`；`--archive` 生成 912 字节存档，
`--restore` 回报「导入完成：会话 1 个 · 记忆 0 条，原文件已备份
`*.bak-20261107-174303`」。

> 中文控制台乱码：Windows 非 UTF-8 代码页的显示限制。
> `starry_cli.py` 已做 `reconfigure(errors="replace")`，不影响功能与退出码；
> 需要正常显示可执行 `chcp 65001`。

## 3. Linux / UOS deb

```bash
sudo dpkg -i 星语Starry-CLI-v12.0.0.deb
starry --version          # 应输出 12.0.0
starry --doctor
```

安装内容：`/opt/starry/` 下为 v12.0 真实源码，`/usr/bin/starry` 是启动器，
另有 desktop 文件与 `postinst`。control 声明
`Package: starry-cli / Version: 12.0.0 / Architecture: all`，
依赖 `python3` 与 `python3-requests / bs4 / markdown`。

> **形态说明**：v11.5 的 deb 内是 PyInstaller 编译的 20MB ELF（免 Python 依赖）；
> 本机无法交叉编译 Linux ELF，v12.0 本机 deb 为「源码 + 系统 python3 启动器」。
> 免依赖 ELF 版由 CI 的 ubuntu job 产出。

## 4. 桌面端 5 个新功能（`Ctrl+K` 命令面板）

| 图标 / 标题 | 做什么 | 什么时候用 |
| --- | --- | --- |
| ✦ 生成本轮星尘卡 | 把本轮「思考起点 / 思考落点 / 回答摘录 / 分片数 / token 量级 / 分支锚点」收成一张 Markdown 小卡，可复制 | 想把一次深度思考存进笔记；**不花 token、不联网** |
| 📐 上下文预算裁剪 | 给出「保留 / 丢弃哪些消息」的计划与 token 账 | 长对话接近上下文上限前，先看计划再决定 |
| 📤 导出 .starry 存档 | 会话 + 记忆 + 元信息打包成带校验的信封 | 换设备、备份、迁移 |
| 📥 导入 .starry 存档 | 校验通过才导入；篡改 / 版本不符 / 结构损坏一律拒绝 | 恢复数据；导入前自动备份原文件 |
| 🩺 运行环境自检 | 版本 / 平台 / 配置目录 / 依赖 / 三端同源状态 | 出问题时先跑这个，把输出贴给开发者 |

五条命令与 CLI 共用 `core.stardust` 与 `core.cli._run_doctor`，
**桌面和命令行看到的结果完全一致**。

## 5. 数据迁移（`.starry` 存档）

```bash
# 旧设备
starry --archive 我的数据.starry

# 新设备（桌面也可走命令面板「导入」）
starry --restore 我的数据.starry
```

存档是 UTF-8 JSON，字段 `magic / version / payload / checksum`，
checksum 为规范化 JSON 的 SHA-256。

- 改一个字符、版本不符、缺字段 → 一律拒绝，**不会写入半份数据**；
- 导入前原文件自动备份为 `*.bak-<时间戳>`；
- 三端（Windows / Linux / 安卓）互导，键顺序规范化，跨端不会误判；
- **定位提醒**：checksum 是完整性校验（防损坏 / 误编辑），不是认证；
  别把它当作加密或防恶意篡改的保证，重要数据请自行加密存储。

## 6. 常见问题

| 问题 | 处理 |
| --- | --- |
| 启动时提示 EULA / 许可 | 按弹窗完成首次确认；许可密钥沿用既有离线校验逻辑 |
| `--doctor` 显示 `markdown 缺失` | 单文件 EXE 有意不收集 `markdown`（只用于桌面 Qt 富文本），标记为可选，不影响 CLI |
| `--doctor` 显示三端同源「跳过」 | 单文件 EXE 内没有源码目录；该项由 CI 发布门禁保证 |
| 找不到配置文件 | `--doctor` 会打印配置目录；Windows 看 `%APPDATA%`，Linux 看 `$XDG_CONFIG_HOME` |
| EXE 被 SmartScreen 拦截 | 未做代码签名，属已知状态；确认来源后选择「仍要运行」 |
| 想验证下载的包没被改 | 对照 `releases/SHA256SUMS-v12.0.0.txt` 与快照内 `MANIFEST.md` 的逐文件 SHA-256 |
| 安卓闪退 / 安装问题 | 见 `使用指南_Android_APK_v12_0.md` 与 `APK鉴定与闪退根因报告_v12_0.md` |

## 7. 升级与卸载

| 平台 | 升级 | 卸载 |
| --- | --- | --- |
| Windows EXE | 直接替换 exe；建议先 `--archive 备份.starry` | 删除 exe；配置留在 `%APPDATA%` |
| Linux deb | `sudo dpkg -i 新版.deb` | `sudo dpkg -r starry-cli` |
| 安卓 | **先卸载旧包再装新包**（签名密钥可能不同），先导出存档 | 系统卸载；应用私有目录随卸载清理 |
| 源码 | `git pull` 后 `pip install -r requirements.txt` | 删除目录 |

历史大版本 v11.5.0 的完整快照保留在 `releases/星语Starry-v11.5.0/`，
**未覆盖、未删除**，可随时回退对照。

## 8. 出问题时的反馈清单

请把以下信息一起提供，能大幅缩短定位时间：

1. `starry --doctor` 的完整输出（或桌面「🩺 运行环境自检」结果）；
2. 版本号（12.0.0）与平台（Windows / Linux / UOS / Android）；
3. 复现步骤与期望 / 实际结果；
4. 安卓端把「诊断」页内容与 `starry-crash.log` 一起复制过来
   （**注意自行抹掉 API Key 等敏感信息**）。
