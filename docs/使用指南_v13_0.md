# 使用指南 · 星语 Starry v13.0.0

> 本版重点在**电脑端**：整体项目 → 多线并行 → 自动更新，桌面工作台与命令行等价可用。
> Windows 专册见 `使用指南_Windows_EXE_v13_0.md`，Linux / UOS 专册见 `使用指南_Linux_DEB_v13_0.md`。

---

## 0. 一句话上手

```bash
starry --workbench
```

不需要 API Key、不需要联网、不需要装数据库。这条命令会打印环境、规划一个整体项目、
分两波并行跑完、显示 100% 进度、给出更新状态与常用命令速查。

桌面端：`python main.py` → `Ctrl+K` → 输入「工作台」→ 打开整体项目工作台。

## 1. 三种入口

| 入口 | 启动 | 适合 |
| --- | --- | --- |
| 桌面 GUI | `python main.py` | 可视化任务树、双击看结果明细、导出报告 |
| 命令行 / EXE / deb | `starry --workbench` | 终端、脚本、CI、SSH |
| Python API | `from core import project, parallel, updatecheck` | 二次开发，见 `API开放文档_v13_0.md` |

三者共用同一份逻辑，结果一致。

## 2. 整体项目：核心概念

| 概念 | 含义 |
| --- | --- |
| 项目 | 一个目标 + 一组任务 + 依赖 + 状态 + 产物，可存成 `.starryproj` |
| 任务 | 有 `kind`（text/check/report/chat）、`depends`、`status`、执行结果 |
| 分波 | 无依赖的任务第一波并行；依赖全部完成的任务进入下一波 |
| 汇总任务 | 默认模板里最后一条，依赖前三条，自动排到第二波 |

默认模板：

```
第一波（3 条并行）  t1 资料盘点   t2 要点提炼   t3 方案草拟
第二波（1 条汇总）  t4 结果复核与汇总   depends=[t1,t2,t3]
```

任务状态：`pending → running → done / failed / skipped`。
依赖失败时下游标 `skipped`，循环依赖不会卡死。

> 「整体项目」在「多线并行」之前：先有项目，才有并行；并行只是项目的调度方式。

## 3. 命令行完整用法

### 3.1 规划与执行

```bash
# 只规划，不执行
starry --project "调研并撰写发版方案"

# 分波并行执行（4 条线）
starry --project "调研并撰写发版方案" --parallel --workers 4

# 带超时与重试
starry --project "..." --parallel --workers 3 --timeout 10 --retries 2

# 保存 / 载入项目
starry --project "写一本书" --parallel --project-save 我的项目.starryproj
starry --project-load 我的项目.starryproj
starry --project-load 我的项目.starryproj --parallel    # 只跑剩余 pending
```

`.starryproj` 带 SHA-256 校验：文件被改动、版本不符、magic 不对，一律拒绝载入。

### 3.2 工作台总览

```bash
starry --workbench
```

输出五段 Markdown：运行环境 / 整体项目 / 多线并行执行 / 自动更新 / 常用命令。
适合截图、写进 CI 日志、或作为「这版能不能用」的一键体检。

### 3.3 自动更新

```bash
# 未配置更新源时的确定性结论（离线，不发网络请求）
starry --update-check

# 本地清单离线校验
starry --update-check --update-manifest update.json

# 远程清单（只读 GET，6 秒超时）
starry --update-check --update-url https://your.host/update.json
export STARRY_UPDATE_URL=https://your.host/update.json   # Linux / macOS
```

Windows 下用 `set STARRY_UPDATE_URL=...` 或 PowerShell 的 `$env:STARRY_UPDATE_URL = "..."`。

工具**只做判定**，不自动下载、不自动替换程序。输出会列出资产名、大小、
下载地址和 SHA-256，请自行从可信来源下载后核对哈希。

生成本地清单（从真实资产计算哈希）：

```bash
python scripts/gen_update_manifest.py --version 13.0.0
```

### 3.4 真实模型（可选）

默认三条并行线是本地确定性执行（零 token）。若项目里有 `chat` 类任务，
且已配置服务商与 API Key，可显式启用：

```bash
starry --project "..." --parallel --execute
```

未配置 Key 时 `chat` 任务会明确报错并被隔离，不影响其它线。

## 4. 桌面工作台

`Ctrl+K` 打开命令面板，搜索下列任一命令：

| 命令 | 作用 |
| --- | --- |
| 打开整体项目工作台 | 打开空白工作台 |
| 从当前对话规划项目 | 用最近一次提问作为目标，自动规划 |
| 规划并多线并行执行 | 一键规划 + 执行 |
| 保存整体项目 | 导出 `.starryproj` |
| 载入整体项目 | 从 `.starryproj` 恢复 |
| 检查版本更新 | 校验本地 `update.json` |

工作台内操作顺序：

1. 顶部输入目标 → 点 **① 规划项目**（或按回车）；
2. 点 **② 多线并行执行**，左侧任务树刷新、进度条到 100%；
3. **双击任一任务**可在右侧查看它的状态、依赖、结果与错误；
4. 底部按钮：保存 `.starryproj` / 载入项目 / 导出报告 `.md` / 检查更新。

> 界面明确写着「默认离线执行，不消耗 token」——不需要先配 Key 就能体验完整流程。

## 5. v12 能力（全部保留）

```bash
starry --doctor                    # 环境 / 版本 / 依赖 / 三端同源自检
starry --budget 4096               # 上下文裁剪计划
starry --archive 备份.starry        # 导出会话 + 记忆
starry --restore 备份.starry        # 导入（先验签、自动备份原数据）
starry -p "你好" --echo             # 对话后附星尘卡
```

桌面命令面板里「星尘卡 / 上下文预算 / 导出导入存档 / 环境自检」也仍可用。
`.starry`（会话存档）与 `.starryproj`（项目存档）互不干扰。

## 6. 数据位置

| 平台 | 位置 |
| --- | --- |
| Windows | `%APPDATA%\ai-desktop-assistant` |
| Linux / UOS | 由 `core.config.get_config_dir()` 按 XDG 规则决定 |
| 隔离测试 / CI | 设 `STARRY_DATA_DIR`（仅影响 gateway 统计与预算数据） |

v12 的教训：Windows 上 `HOME` 不控制 `expanduser("~")`，
需要隔离网关数据请用 `STARRY_DATA_DIR`，不要只改 `HOME` / `APPDATA`。

## 7. 常见问题

| 现象 | 原因 / 处理 |
| --- | --- |
| `--project-load` 报「拒绝载入」 | 文件被改动或不是 `.starryproj`；用 `pack_project()` 重新生成 |
| `--parallel` 没有任何执行输出 | 载入的项目任务已全部 `done`，`ready_tasks()` 为空；属预期，不会重复执行 |
| 汇总任务显示 `skipped` | 上游任务失败或存在循环依赖；双击任务看 `error` 字段 |
| `--update-check` 说「未配置」 | 正常离线结论，不是故障；见 §3.3 配置方式 |
| Windows 终端里 `✦` 显示为 `?` | cp936 编码兜底，中文内容完整；`_emit()` 保证不因打印崩溃 |
| `--execute` 报缺 API Key | 需先在设置或 `config.json` 配服务商；默认离线模式不需要 |
| EXE 首次启动慢 | 单文件包需解压，约数秒；属正常 |
