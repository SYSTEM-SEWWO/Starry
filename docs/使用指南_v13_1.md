# 使用指南 · 星语 Starry v13.1.0（Skills Hub / GUI EXE / 技能更新）

> 本版主题：**还想要 GUI 版 EXE + 兼容 GitHub / Claude Code 等主流的 Skills Hub + 更新功能**。
> 三件事都已落地，且全部**离线可跑**：不需要 API Key、不需要联网、不需要额外装依赖。

---

## 1. 三分钟上手

### 1.1 GUI 桌面版（新增）

双击 `dist/星语Starry.exe`（Windows）即可启动，托盘常驻、关窗不退出。

- `Ctrl+K` 打开命令面板 → 「🧩 打开 Skills Hub」或「🔄 检查技能更新」
- Skills Hub 左侧列出技能，点一下右侧显示**指令正文原文**
- 顶部搜索框支持名称 / 描述 / 标签 / 正文，空格分词是 AND 关系
- 「📁 添加源」可选一个本地技能目录；「⬇ 导入为星语技能」把技能写进技能库
- 「📤 导出 hub.json」生成可分发的技能清单；「🔄 检查技能更新」选一份 `hub.json` 做离线比对

### 1.2 CLI / CLI EXE

```bash
python starry_cli.py --hub                       # 列出全部技能
python starry_cli.py --hub-search api           # 搜索
python starry_cli.py --hub-info release-checklist   # 查看正文
python starry_cli.py --hub-source ./my-skills --hub   # 追加一个本地源
dist\星语Starry-CLI.exe --hub                  # Windows EXE 同理
starry --hub                                  # Linux deb 安装后
```

### 1.3 Linux / 统信 UOS

```bash
sudo dpkg -i dist/星语Starry-CLI-v13.1.0.deb
starry --hub
```

deb 里已包含 `core/hub.py` 与 `/opt/starry/skills/`，装完直接可用，无需下载。

## 2. 兼容哪些生态

| 生态 | 载体 | 默认扫描位置 |
| --- | --- | --- |
| Claude Code | `SKILL.md` + YAML frontmatter | `~/.claude/skills/<name>/SKILL.md`、`<project>/.claude/skills/` |
| GitHub / Copilot / Agent Skills | 同规范 `SKILL.md` | `.github/skills/`、`<repo>/skills/`、扁平 `*.skill.md` |
| WorkBuddy | `SKILL.md` | `~/.workbuddy/skills/`、`<project>/.workbuddy/skills/` |
| 星语自有 | `config.json` 的 `skills` 数组 | 由 `Hub(starry_skills=...)` 并入 |
| 通用 Hub 清单 | `hub.json` / `skills.json` | 本地文件（只读，不执行其中内容） |

**不需要改写现有技能包**。frontmatter 的常见写法都认：

```yaml
allowed-tools: Read, Bash, Grep        # 内联逗号
allowed-tools:                         # YAML 列表续行
  - Read
  - Grep
tags: [api, review, docs]              # 内联数组
description: >                         # 块标量
  多行说明会被折叠成一行
metadata:                              # 一层嵌套映射
  version: 1.2.0
```

`name` 以 frontmatter 声明为准；缺失时才用目录名 / 文件名兜底。
`version: 1.2.0` 这类三段版本号按字符串保存，不会被解析成浮点数。

仓库自带的三份示例在 `skills/`：
`claude-code-style/SKILL.md`、`github-copilot-style/SKILL.md`、`flat-skill.skill.md`。

## 3. 导入技能（唯一的写操作）

```bash
python starry_cli.py --hub-import release-checklist
```

执行后 `config.json` 的 `skills` 数组新增一项：

```json
{"id": "hub_github-release-checklist", "name": "release-checklist",
 "description": "…", "prompt": "# 发版前检查清单…", "icon": "🧩"}
```

之后可在桌面「技能」菜单中选用。注意：

- 同 id 重复导入是**覆盖更新**，不会产生重复项；
- 清单里只有元数据、没有正文的技能会被拒绝导入（提示词不能是空的）；
- 请只导入你信任的技能——正文会被写进本地配置，虽不会被执行，但会作为提示词注入。

## 4. 技能更新功能（与程序版本更新是两件事）

v13.1 有**两条独立的更新线**：

| | 程序版本更新（v13.0 已有） | 技能更新（v13.1 新增） |
| --- | --- | --- |
| 清单 | `update.json` | `hub.json` |
| 比对对象 | `core.config.APP_VERSION` vs 远端版本 | 本地技能 `sha256` / `version` vs 清单条目 |
| CLI | `--update-check --update-manifest update.json` | `--hub-update --hub-manifest hub.json` |
| GUI | 工作台「检查更新」 | Skills Hub「检查技能更新」 |
| 结果 | 列出平台资产与 SHA-256 | 列出 新增 / 变更 / 移除 技能 |

### 4.1 生成一份清单

GUI：「📤 导出 hub.json」直接保存。
CLI / Python：

```python
from core import hub as hb
m = hb.build_hub_manifest(hb.Hub().discover(), hub_version="1.0.0")
import json; json.dump(m, open("hub.json", "w", encoding="utf-8"),
                       ensure_ascii=False, indent=2)
```

### 4.2 检查更新

```bash
python starry_cli.py --hub-update --hub-manifest hub.json
# 清单校验：通过
# 结论：本地技能已是最新  /  技能有更新：新增 1 / 变更 2 / 移除 0
```

清单结构、digest、每条 `sha256` 都会被严格校验；篡改 `notes` 或任一字段都会输出
「清单校验：失败」并返回非零退出码，且**不会**据此判定有更新。

> ⚠️ `digest` 是**完整性校验，不是签名认证**。请只从可信 HTTPS / GitHub Releases /
> 官方仓库获取 `hub.json`。Hub 不会自动下载或安装任何技能。

## 5. GUI EXE 自检（无显示器也能验证）

窗口程序默认不弹控制台，`sys.stdout` 可能为 `None`，因此自检结果写入文件：

```bash
星语Starry.exe --version --out version.txt
星语Starry.exe --selftest --out selftest.json
python scripts/smoke_gui_exe.py --exe dist/星语Starry.exe --expect-version 13.1.0
```

`selftest.json` 包含版本号、通过数 / 总数、逐项结果，覆盖：
版本真源、`core.hub`、随包 `skills/`、HubDialog 装配 / 搜索 / 清单自校验、
WorkbenchDialog 装配。CI 的 `build-windows.yml` 用同一个脚本做门禁。

## 6. 与 v12 / v13.0 能力的关系

全部保留，命令不变：

```bash
python starry_cli.py --doctor
python starry_cli.py --budget 4096
python starry_cli.py --archive 备份.starry
python starry_cli.py --project "调研并撰写发版方案" --parallel --workers 4
```

## 7. 常见问题

**Q：`--hub` 一个技能都没列出来？**
A：确认 `skills/` 目录存在；或用 `--hub-source <目录>` 显式指定。
EXE / deb 里已内嵌 `skills/`，正常开箱即有 3 个示例技能。

**Q：我装了 Claude Code 技能，为什么没出现？**
A：检查是否位于 `~/.claude/skills/<name>/SKILL.md`，且 frontmatter 有 `name` 或目录名。
也可直接 `--hub-source ~/.claude/skills`。

**Q：`--hub-update` 说每个技能都变了？**
A：v13.1 已修：比对用清单**声明**的 `sha256`，且 id 与本地同源。
如果你手工写的清单没带 `id` / `source`，请从「导出 hub.json」生成，不要手写。

**Q：GUI EXE 双击没反应？**
A：先跑 `--selftest --out result.json` 看自检结果；托盘图标默认常驻，
关窗不会退出进程，可从任务管理器或托盘菜单退出。
