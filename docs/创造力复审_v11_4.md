# 创造力复审 · v11.4.0

> 视角：创新点 / 产品化思路 / 差异化。评审对象：消息引用 / 分支对话。

## 1. 把「分支」从版本控制借到对话管理
- 「从任意历史消息分支出新会话」对齐 ChatGPT / Claude 网页端的「从此处新建分支」，本质是把 **Git 的 branch 心智**引入对话：一个问答点可以分叉出多条探索路径，原对话始终是「主干」。
- 落地不止于 UI：`branched_from={session_id,index}` **溯源字段** + `list_branches` 聚合 + 「🌱 分支列表」跳转，形成可回溯的分支树雏形，为后续「合并 / 对比分支回答」留出结构空间。

## 2. 把碎片交互抽象成可测纯函数
- 「@ 某条消息追问」在多数产品里是一段耦合在 UI 里的字符串拼接；本轮抽象为**两个无副作用纯函数**：`format_quote`（引用块格式化）+ `build_quoted_prompt`（引用 + 上下文指令拼装）。
- 好处：可单测、可被桌面 / 安卓 / 未来插件复用、可独立调参（如 `QUOTE_MAX_CHARS`），且「请结合引用内容作答」是**显式的提示工程**，比单纯贴原文更能引导模型聚焦。

## 3. 一框两用的复用式设计
- 引用与分支本质是「选一条消息 + 不同后续动作」，因此用 `MessagePickerDialog(mode=...)` **一个对话框两种模式**承载，通过标题 / 提示 / 是否显示输入框区分。以最小 UI 表面积覆盖两种能力，减少视觉与维护负担。

## 4. 分层按「操作成本」设计入口
- 「↩️ 引用最后回复」零选择成本（快捷）、「💬 引用消息追问」可选任意消息（完整）、「🌿 分支对话」与「🌱 分支列表」覆盖创建与回看——四条命令按复杂度递进，兼顾新手与重度用户。

## 5. 隐性体验问题的产品化预防
- 识别「启动补 system 提示导致索引偏移」这一会让功能「选错消息」的隐性 bug，用「操作前落库对齐」从流程上消除，而非靠用户手动规避——把健壮性做进默认路径。

## 6. 与前序版本形成能力闭环
- v11.1 检索 → v11.2 标签/编辑删除 → v11.3 收藏/总结/批量导出 → **v11.4 引用/分支**：桌面端已从「能对话」演进到「能检索、能标注、能沉淀、能分叉」，且每一步都坚持 `core` 纯逻辑同源，安卓端零成本共享逻辑底座。

**结论**：v11.4.0 在成熟交互范式上做了可测、可复用、可回溯的工程化落地，一框两用与分层入口体现克制创新，与既有能力形成闭环，创造力维度正向。
