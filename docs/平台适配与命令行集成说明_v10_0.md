# 平台适配与命令行集成说明 · V10.0

> 本文档说明 V10.0 的「一处代码、多端分发」策略：如何在统一工程内适配
> **Windows / Linux / 统信 UOS / Android(Termux)** 四类平台，并通过「无界面命令行版」
> 把同一套 AI 能力搬到无桌面的服务器、CI、Termux 与命令提示符中。

## 1. 为什么要做平台分发 + 命令行

- 桌面 GUI 版（PyQt5）依赖图形环境，无法在服务器 / CI / Termux / 旧机器上运行；
- 用户场景分化：有人要双击即用的 GUI，有人要在脚本里 `curl` 式地调用大模型；
- 国产操作系统（统信 UOS、麒麟）需要 `.deb` 这类合规分发形态；
- Android 用户希望用 Termux 直接跑，或进一步封装成 APK。

V10.0 的答案是：**保留桌面 GUI 版不动，新增一个纯 `core` 层、零 PyQt 依赖的命令行版**，
再用「版本后缀」把同一份完整工程切分为各平台各自的发布包。

## 2. 平台检测（core/platforms.py）

| 函数 | 作用 | 证据 |
| --- | --- | --- |
| `detect_platform()` | 返回 `windows/macos/uos/linux/android/unknown` | `core/platforms.py:56` |
| `is_uos()` | 读 `/etc/os-release`，判定 `ID=uos` 或 `UnionTech` | `core/platforms.py:25` |
| `is_android_termux()` | 读环境变量 `TERMUX_VERSION` | `core/platforms.py:39` |
| `platform_suffix()` | 返回各端版本后缀：`windows-cli / linux-cli / uos / android` | `core/platforms.py:106` |
| `platform_package_hint()` | 返回该端默认打包形态说明 | `core/platforms.py` |

检测完全基于标准库（无 PyQt），因此命令行版与桌面版共用同一份逻辑。

## 3. 无界面命令行引擎（core/cli.py）

设计要点：

- **零 GUI 依赖**：仅导入 `core.config / core.api / core.agent.* / core.platforms /
  core.memory / core.reasoning / core.rea / core.web_sites`，全部为纯逻辑模块
  （验证：`grep -rln PyQt5 core/agent core/cli.py core/platforms.py` 无命中）。
- **复用真实能力**：`build_client()` 与桌面版 `_effective_client` 同构（`core/cli.py:93`）；
  `collect_chat()` 直接驱动 `ChatClient.chat_stream`（`core/cli.py:50`）；
  `collect_agent()` 复用 `AgentRuntime` 多轮工具循环（`core/cli.py:64`）。
- **纯函数可单测**：`collect_chat/collect_agent` 不触碰 IO，自测用假 client 断言；
  `run_cli(argv, out=)` 可注入输出流，便于断言打印结果。
- **安全护栏**：网页接入型服务商（如 `web_deepseek`）在 CLI 被显式拒绝，提示改用桌面版
  （`core/cli.py:29` 的 `is_web_site` 判断）。
- **能力贯通**：自动注入长期记忆（`_build_messages`，`core/cli.py:125`）、支持智能体工具、
  支持 REA 逆向工程预设并入（`--add-rea`，复用 V9.0 的 `ensure_rea_preset`）。

### 命令行参数

```
python3 starry_cli.py "你的问题"
python3 starry_cli.py -f prompt.txt --json
python3 starry_cli.py --platform
python3 starry_cli.py --agent "列出当前目录文件"
python3 starry_cli.py --provider deepseek --model deepseek-chat "你好"
python3 starry_cli.py --add-rea        # 把 REA 逆向工程 MCP 预设并入配置
```

详见《命令行使用指南.md》。

## 4. 各平台版本后缀与打包脚本

同一份完整工程，按平台后缀分发（每个文件夹都含完整源码 + 全部 md + 主文件）：

| 平台 | 版本后缀 | 打包脚本 | 产物形态 |
| --- | --- | --- | --- |
| Windows | `windows-cli` | `scripts/build_windows_cli.ps1` | `星语Starry-CLI.exe`（console） |
| Linux | `linux-cli` | `scripts/build_linux_cli.sh` | `星语Starry-CLI`（ELF） |
| 统信 UOS | `uos` | `scripts/build_uos.sh` | `.deb` 安装包 |
| Android | `android` | `scripts/build_android.sh` | Termux 直跑 / 可选 APK |
| 桌面 GUI | （无后缀，全量） | `scripts/build_linux.sh` / `build_windows.ps1` / `build_macos.sh` | 单文件 GUI |

- 命令行版 PyInstaller 配置：`starry_cli.spec`（入口 `starry_cli.py`，`console=True`，
  不收集 `ui.*`，产物显著小于桌面版）。
- 桌面版 PyInstaller 配置：`starrystar.spec`（已补 `core.platforms` 隐藏导入）。

## 6. 已知边界（诚实标注）

- 真实 `.exe` / `.apk` 需在对应平台（Windows SDK / Android NDK）本地构建；
  本仓库提供**已验证的打包脚本与命令**，而非在 Linux 沙箱内伪造产物。
- 桌面 GUI 版仍为 PyQt5 实现，UOS / Linux 桌面端依赖 X11/Wayland 与 Qt 运行库
  （`build_linux.sh` 已提示安装 `libxcb-cursor0` 等）。
- 命令行版不覆盖网页接入型服务商（如 DeepSeek/智谱清言/豆包的网页版），此类需浏览器 harness。
