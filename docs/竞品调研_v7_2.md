## 二、从竞品学到的三条关键洞察

### 洞察 1：「主动一点」比「更强大」更容易被感知（Clippy / Desk Pet）

Clippy 是一个单文件 Python 桌面伴侣：**闲置漫游（Idle Roaming）**、**随机提示气泡
（Random Tips）**、选中文字旁主动给建议。它并不比 ChatGPT 强，但「有生命感」的
交互让留存完全不同——这是「工具」与「伙伴」的分界线。

> 落地：悬浮球「待机漫游 + 随机提示气泡（时段感知）」。
> 取舍：不做物理引擎/宠物皮肤（体积与复杂度不划算），只做**轻量的拟人感**。

### 洞察 2：「划词即问」是桌面场景的杀手入口（Cherry Studio 划词助手）

在任意应用选中文字 → 浮动工具条 → 解释 / 翻译 / 总结 / 优化。它把「复制、切窗口、
粘贴、加提示词」四步压成一步，是桌面端相对 Web 端的**结构性优势**。

> 落地：`Ctrl+Shift+Q` 召唤迷你提问窗，读选区/剪贴板，6 个动作 + 补充要求，
> 一键合成提示词并发给主窗。取舍：不做常驻浮动工具条（会干扰其他应用、跨平台不稳）。

### 洞察 3：「轻」本身就是竞争力（Clippy 单文件 / Jan 离线）

用户对「装个客户端」的容忍度在下降：Docker、依赖、几百 MB 体积都会劝退。
本产品已是 PyQt5 单文件路线，本轮继续减法：

- `starrystar.spec` 排除 15 个未使用的 Qt 模块（WebEngine/Qml/Quick/3D/Multimedia/Sql…）；
- 4 个存储类（会话/统计/资料库/自动化）的 `save()` 完全重复 → 抽为 `core/storage.py`
  的 `save_json/load_json`，一份实现；
- 新功能全部落到小而集中的模块（`core/quickask.py` 130 行、`core/idle_tips.py` 100 行、
  `ui/quick_ask.py` 200 行），没有往大文件里堆。

## 三、明确「不跟」的功能（以及理由）

| 竞品功能 | 为何不跟 |
| --- | --- |
| MCP 服务器生态 | Python 端无轻量成熟实现；引入后体积/依赖显著膨胀，与「轻」冲突 |
| AI 绘画 / 视频 | 与本产品「对话 + 干活」定位偏离，且必然拉大体积 |
| 多模型并排对比（Msty 式） | 已有「多专家会诊」覆盖 80% 场景；并排对比需要重构消息布局，收益/成本比低 |
| 300+ 预设助手 | 用「技能 + 插件市场 + 划词动作」覆盖高频场景，堆预设数量对留存帮助有限 |
| 云同步 / WebDAV | 隐私优先是卖点，保持纯本地；已有配置备份 |

## 四、本轮（v7.2）落地清单

1. **划词提问**：`core/quickask.py` + `ui/quick_ask.py` + 全局热键 `Ctrl+Shift+Q`
   + 命令面板入口（命令数 22 → 24）。
2. **桌面拟人化**：悬浮球待机漫游（8s 后开始、约 11s 一次、弹簧微浮动）+
   随机提示气泡（22s 后首句、26s 间隔、淡入淡出、跟随球体）。
3. **轻量化**：spec 排除未用 Qt 模块；存储层去重；新增模块保持小体量。
4. **生产链**：CI `build-windows` job 打单文件 exe（脚本复用 + 启动冒烟 + Artifact 上传）；
   本地已用 shared-lib Python 实测打包并启动冒烟（Linux 134MB 单文件）。
