# 美术复审 · v13.1.0

> 视角：新增 Skills Hub 对话框是否与 v13.0 工作台保持同一套视觉语言，
> 信息层级是否清楚，状态是否可辨识，以及是否引入新的可读性风险。

## 1. 一致性检查

| 项 | 工作台（v13.0） | Skills Hub（v13.1） | 结论 |
| --- | --- | --- | --- |
| 标题字重 / 色值 | `16px / 700 / #0f172a` | 同 | 一致 |
| 说明文字 | `11px / #64748b` | 同 | 一致 |
| 按钮 | `_BTN` 白底描边 + `_PRIMARY` 蓝底 | 复用同一常量 | 一致 |
| 列表 / 详情容器 | `_TREE` 白底 + `_BROWSER` 浅灰底 | 同 | 一致 |
| 布局 | `QSplitter` 左树右报告 | `QSplitter` 左表右详情 | 一致 |
| 圆角 / 边距 | `10px` / `14,12,14,12` | 同 | 一致 |

`ui/hub_dialog.py` 直接复制了工作台的 QSS 常量而不是另起一套，
这是刻意的：新窗口不应该看起来像另一个软件。

## 2. 信息层级

```
标题（一句话说明本版主线）
说明（版本 + 只读安全提示）
─────────────────────────────
搜索框  |  🔄 刷新  📁 添加源
─────────────────────────────
┌ 来源 │ 名称 │ 版本 │ 说明 ┐  ┌ 技能详情 ┐
│ 表格（可点击）            │  │ 说明/工具/正文 │
└──────────────────────────┘  └───────────┘
状态行（共 N 个 / 命中 M 个）
─────────────────────────────
       ⬇ 导入  🔄 检查更新  📤 导出  关闭
```

- **来源**单独成列，是本次设计的重点：用户最关心「这个技能从哪来」，
  因此把 `source` 放到第一列并用 `` `code` `` 样式呈现，而不是塞在说明里。
- **主操作按钮用蓝色**（导入），次操作用白底描边，层级不靠位置靠权重，
  与工作台「并行执行」按钮的处理一致。
- **状态行**随搜索实时更新「命中 N / 共 M」，避免列表为空时用户不知道是
  「没扫描到」还是「搜索没命中」。

## 3. 可读性细节

| 细节 | 处理 |
| --- | --- |
| 描述里的 `|` 会撑破 Markdown 表格 | `render_catalog` 自动转义为 `\|`，单测锁死 |
| 描述过长 | 列表列截断到 80 字符，详情区保留全文 |
| 正文里的 Markdown 标记被渲染吞掉 | 详情区用 `setPlainText` **原样展示**，便于复制与核对（也利于 offscreen 自检） |
| 版本缺失 | 显示 `—`，不留空白 |
| 工具为空 | 表格显示 `—`，不显示 `None` |
| 搜索无结果 | 右侧显示「没有匹配的技能。」，状态行显示命中 0 |

## 4. 状态双编码（延续 v13.0 原则）

不用**颜色单独**表达状态：
- 来源用文字标签 + 等宽样式；
- 更新结果用「新增 / 变更 / 移除」+ 数量 + 名称列表；
- 校验结果用「通过 / 失败」文字，而不是只靠红绿点。
色弱用户与灰度截图下仍可辨识。

## 5. 遗留建议（不阻断本版）

1. **暗色主题适配**：QSS 目前是硬编码浅色值，与工作台一样。
   项目有「墨夜 / 深蓝」主题，但两个新对话框尚未跟随 `cfg.appearance.theme`。
   建议下一版抽出 `ui/theme.py` 统一供给，避免逐个对话框改。
2. **表格列宽自适应**：目前固定 `110/190/80`，超长技能名会被截断；
   可考虑 `QHeaderView.ResizeToContents` + 最大宽度限制。
3. **技能图标**：统一用 🧩，尚未按 `meta.icon` 或来源区分。
   来源列已承担识别职责，优先级不高。

## 6. 评价

**A-**。没有引入新的视觉语言，信息层级围绕「来源 → 名称 → 正文」组织得干净；
把「随包技能是否真的可用」做成 GUI 自检项，也让视觉层的空列表不再可能被误判为
「设计如此」。扣分点是暗色主题仍未覆盖新对话框。
