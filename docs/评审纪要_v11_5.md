## 二、逐项纪要

### 1. 代码安全性评估
- `core/insights.py` 全部为纯函数：不写文件、不发起网络、不执行动态代码，
  返回新对象不修改入参（单测 `test_merge_no_mutation` / `test_diff_empty_and_no_mutation` 验证）。
- `_emit` 的兜底只捕获 `UnicodeEncodeError`，**不吞其它异常**，避免掩盖真实故障；
  最外层 ASCII 兜底亦仅作用于打印，不影响业务逻辑。
- `merge_into` 显式拒绝自合并与不存在的会话；`starred` 下标经 `mapping` 重映射后
  排序去重，杜绝越界下标引用。
- `estimate_tokens` 只做字符统计，不解析外部输入为代码。
- 详见 `docs/代码安全性评估_v11_5.md`。

### 2. HR 复审
- 新增 `docs/Windows_EXE_构建指南.md` 把「此前只能靠经验」的 Wine 步骤写成
  可复制命令（含 `cmd /c` 踩坑），新维护者无需口头传授即可复现。
- 9 份 `_v11_5` 文档 + API 文档 + README/CHANGELOG 段落齐备，
  与 v11.3/v11.4 的文档命名规范一致。
- 单测 22 项带清晰命名，覆盖边界（空会话、越界、多模态、旧数据兼容）。
- 详见 `docs/HR复审_v11_5.md`。

### 3. 美术复审
- `ui/insight_dialog.py` 沿用 `message_picker_dialog.py` / `starred_dialog.py`
  的圆角、配色、留白与按钮排布，视觉语言统一。
- `format_stats_markdown` / `format_diff_markdown` 用 Markdown 表格 + 分节，
  在 QTextBrowser 中层级清晰；`setMarkdown` 不可用时退化为纯文本不崩。
- 命令面板 3 个新图标（📊🔀🧬）语义直观，与既有「⭐📌📋🌿」序列协调。
- 详见 `docs/美术复审_v11_5.md`。

### 4. 资深程序员复审
- 把分析逻辑从已 700 行的 `sessions.py` 拆到独立 `core/insights.py`，
  「存储层 / 分析层」职责分离，且 **insights 不 import sessions**，
  从根上规避 `SessionStore.merge_into` 的循环依赖。
- 对比算法选「最长共同前缀 + 同位置对齐」而非通用 LCS：对分支场景更稳定、
  结果可解释，且 `common_prefix_len` 被 diff 与 merge 复用，避免两套逻辑漂移。
- `merge_messages` 返回 `mapping` 供上层重映射收藏下标，是纯函数与状态层
  协作的干净边界；`SessionStore.merge_into` 只做薄薄一层落库。
- AST 校验确认 `delete/append/messages` 等方法仍归属类内（延续 v11.3 踩过的坑）。
- 详见 `docs/资深程序员复审_v11_5.md`。

### 5. GitHub 复审
- **本轮最大发现**：`ci.yml` 虽有 `build-windows` job，但只在 `push main`/PR
  触发、只传 14 天 Artifact、**从不进 Releases**；故「打包成点 exe」从未闭环。
  新增 `build-windows.yml` 推 `v*` tag 即发布真 exe。
- 两个 workflow 并发触发同一 tag：Windows 侧用 `append_body: true` 且**不设
  `name`**，只追加资产，避免覆盖安卓侧创建的 Release 标题/说明。
- `.gitignore` 已含 `.venv-cli/`、`android/dist/`、`*.apk`，exe 与 APK 不入库，
  由 CI 产出。
- 详见 `docs/GitHub复审_v11_5.md`。

### 6. 反复优化
- Wine 链路两次失败：① 直接运行报 `init_sys_streams / [WinError 6]`
  → 改走 `cmd /c` 提供控制台；② 首次出 exe 后 `--version` 抛
  `UnicodeEncodeError` 秒退 → 双层编码兜底后 UTF-8 / cp1252 双场景退出码 0。
- 版本号升级后**重新打包** exe / CLI / deb / APK，杜绝 v11.3 那种
  「分发旧构建」的复发（本轮脚本内置 [3.5] 源码版本核验步骤）。
- **全量自测首次跑通并暴露 4 个问题**：`selftest.py` 780 项中 3 项失败——
  命令面板数写死 31（实际 43）、「导出」搜索期望 1 条（V11.3 起有 2 条）
  属过时断言；`搜索无结果` 则暴露了 **V11.1 遗留的中文单字误命中**
  （`_tokenize` 把中文拆成单字，标题含「的」即得分召回无关会话）。
  已修 `_tokenize` 为「连续 CJK 片段 + 二元组、丢弃单字」、
  `search_ranked` 无有效 token 时返回空列表，并把两处断言改为结构不变量；
  修复后 **780/780 全绿**。
- 因 `core/sessions.py` 变更，APK / CLI / deb / Windows exe **全部重新构建**，
  并重新生成 5 个版本文件夹与 zip，杜绝「源码已修、产物仍旧」。
- 桌面 / 安卓 `core/` 四处同步并用 `diff -q` 校验字节一致。
- 详见发布说明 `docs/RELEASE_NOTES_v11_5.md`。

### 7. 创造力复审
- 在**纯 Linux 沙箱**里用 Wine 装 Windows Python + PyInstaller 交叉产出
  PE32+ exe，把「无 Wine 所以没 exe」这一长期借口变成实际交付。
- 把 v11.4 的「分支」这一已有数据结构复用为对比/合并的**共同前缀锚点**，
  让新旧功能形成连贯的能力链，而非孤立堆砌。
- 离线 `estimate_tokens` 用 CJK / 拉丁字符分治给出可用的量级参考，
  零依赖即可做「对话洞察」。
- 详见 `docs/创造力复审_v11_5.md`。

**结论：v11.5.0 全链路复审通过，准予发布。**
