**流程**：代码安全性评估 → HR 复审 → 美术复审 → 资深程序员复审 → GitHub 复审 →

## 二、评审过程中发现并修复的问题

| # | 发现方 | 问题 | 处理 | 验证 |
| --- | --- | --- | --- | --- |
| P1 | 代码安全性评估 | `make_release.py` 把 `"*.keystore"` 写进**精确匹配集合**，通配符永不生效；`ignore_patterns` 也只列一个固定名，任意名称密钥会进发布 zip | 新增 `EXCLUDE_PATTERNS` + `is_sensitive()`（`fnmatch`）、`ignore_patterns` 补 6 类密钥扩展名、新增 `assert_no_secrets(dest)` 发布前扫描，命中即中止发版 | `my-release.keystore / debug.keystore / upload.p12 / cert.pem / id_rsa.key` 全部 `True`；含 `secret.keystore` 的快照被准确拦出 |
| P2 | 代码安全性评估 | 历史快照 `releases/星语Starry-v11.5.0/android/starry-release.keystore` 含演示私钥 | 按用户要求保留历史完整性，**不删除**；明确标注若公开分发必须轮换；v12.0 快照不含 `releases/` 目录 | 全项目扫描仅此 1 处，已写入评估报告与 GitHub 复审建议 |
| P3 | GitHub 复审 | `release.yml` 的 `git push origin HEAD:main` 在 tag 触发的 detached HEAD 下可能失败 | 现有 `\|\| echo` 兜底不阻断发布，登记为改进项 | 已在两份文档标注 |
| P4 | 资深程序员复审 | `AppConfig.load()` 的 `except: pass` 静默丢弃异常根因 | 现有诊断页 / `--doctor` 已补可观测性；登记下版写入诊断日志 | 已登记技术债 |
| P5 | 代码安全性评估 | `.starry` checksum 属完整性校验而非认证，存在被过度承诺的风险 | 在评估报告与 API 开放文档统一口径为「损坏即拒绝」，不宣称「防篡改」 | 文档口径已一致 |
| P6 | 全量自测终检 | `core/gateway.py` 把统计 / 预算固定在 `~/.starry`；Windows 上 `expanduser("~")` 读 `USERPROFILE`，自测 `HOME=tmp` 隔离无效，读到真实累计数据 → 网关 / 预算 12 项断言失败。此前误判为「环境依赖」 | 新增**可选** `STARRY_DATA_DIR` 注入点（默认路径逐字不变、不迁移数据）；`selftest.py` 顶部统一注入 + 各网关段独立隔离 | Chromium 装好后 767/12、补 `USERPROFILE` 后 774/5、修复后 **779/0**，直接运行无需外部变量 |
| P7 | 全量自测终检 | `_on_web_install()` 只判断系统 Chrome（`find_chromium()`），Playwright **内置**内核已装好仍会启动安装线程重复下载 100+ MB | `core/browser_llm.py` 新增 `chromium_kernel_available()`（纯文件系统探测、不启动 driver）；设置页在已就绪时直接反馈、不启动线程 | 「已就绪时点击安装有反馈（不启动线程）」由 FAIL 转 PASS；内核探测实测 `True` |

## 四、发布准入判定

**准予发布 v12.0.0 的代码、文档、EXE、deb 与完整项目快照。**

但以下三项**必须随发布一同如实说明**，不得省略：

1. **v12.0 修复版签名 APK 二进制未在本机产出**。本机缺 JDK 17 / Android SDK / NDK /
   Gradle / `apksigner`；替换 `app.imy` 会使 v1 摘要与 v2/v3 签名失效，必须重签。
   修复版由 `.github/workflows/build-android.yml` 在推 `v12.0.0` tag 时真实编译，
   并过 `apksigner verify` + `verify_apk.py --strict`。**未伪造 APK**。
2. **无真机 / 无模拟器**，不能声称「真机实测不闪退」。
   可保证的是 8 项缺陷均有文件行号与本机复现依据，且用真实 `core` +
   忠实复刻 Toga 0.5.7 行为的 UI 替身跑通 37 项集成回归。
3. **【已解决】`selftest.py` 全量自测 779 通过 / 0 失败**。
   早期 761/12 曾被误判为「运行环境依赖、CI 干净环境能过」；
   Chromium 内核装好后失败依旧（767/12），补 `USERPROFILE` 隔离后仍剩 5 项，
   最终定位到 `core/gateway.py` 的 `~/.starry` 在 Windows 上不受 `HOME` 隔离
   影响（见 P6）。修复后**无需任何外部环境变量**即可复现 779/0；
   CI 仍保留 `playwright install chromium`。
   **此前发布说明中「属环境依赖」的表述已在本次收尾中更正。**
