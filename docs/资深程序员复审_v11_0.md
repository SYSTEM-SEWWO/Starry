# 资深程序员复审 · V11.0

> 从架构、可维护性、构建正确性、跨端复用度做工程向评审。

## 1. 架构（亮点）

- **单一核心、多端外壳**：`core/` 纯逻辑层被桌面（PyQt5）、命令行（stdlib）、安卓（Toga）三端共用，
  业务逻辑零重复。这是 V8→V11 持续坚持的正确分层。
- 安卓端 `app.py` 仅约 300 行 GUI 胶水，所有能力来自 `core.cli` / `core.agent.runtime`
  / `core.memory` / `core.platforms`，无「另写一套伪实现」。

## 2. 正确性要点

- **安卓主线程网络限制**：`on_send` 用 `run_in_executor` 把阻塞的 `requests` 放到后台线程，
  再以 `loop.call_soon_threadsafe` 回写 UI，规避 `NetworkOnMainThreadException`——这是安卓移植最容易踩的坑，已正确处理。
- **导入安全**：安卓 `core/` 副本已剔除 `workers/models/attachment/hotkey`（PyQt/pynput），
  经 `import core.cli` 实测通过，无残留 GUI 依赖。
- **版本令牌同步**：`APP_VERSION` / `CLIENT_INFO.version` / selftest 断言三者统一为 `11.0.0`，无漂移。

## 3. 构建链路

- 桌面 GUI：PyInstaller `starrystar.spec`（140MB ELF）。
- 命令行：PyInstaller `starry_cli.spec`（33MB ELF，已验证 `--version` / `--platform`）。
- UOS：命令行二进制 + `dpkg-deb` 封装（32MB `.deb`，已验证 `dpkg-deb -I`）。
- 安卓：BeeWare `briefcase` → Gradle → `python-for-android`，CI 真实编译产出 APK。

## 4. 可维护性

- `sources = ["starryandroid", "core"]` 让 briefcase 自动纳入核心；核心更新时安卓端无需改打包配置。
- `build_android_apk.sh` 与 `.github/workflows/build-android.yml` 把「装 SDK/NDK → 构建 → 签名」脚本化，
  降低发版对个人的依赖。

## 5. 风险与建议

1. 安卓 `core/` 为**副本**，与桌面 `core/` 存在漂移风险；建议后续用 git submodule 或 monorepo 软链统一来源。
2. `app.py` 中增量回答标签 `_live_label` 的提交/清除逻辑较隐式，建议抽成 `MessageBubble` 类提升可读性。
3. CI 构建 python-for-android 单次约 20–40 分钟，建议加 `.gradle` / p4a 缓存以提速。

## 6. 评分：**A-**（架构优秀、关键安卓坑已规避；副本同步与可读性可再优化）
