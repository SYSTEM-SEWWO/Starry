# 资深程序员复审 · v11.4.0

> 视角：架构 / 可维护性 / 边界处理 / 隐性 bug 预防。评审对象：消息引用 / 分支对话全链路。

## 1. 分层与同源
- 新能力**零 Qt / 零安卓依赖**，全部落在纯逻辑 `core/sessions.py`；`core/sessions.py` 与 `android/core/sessions.py` 保持**字节一致**（已 `diff` 校验），延续「一处代码多端分发」。
- UI 层（命令面板 + `MessagePickerDialog`）只做「选择 + 调用」，不含业务逻辑；`app/assistant.py` 新增方法均为薄适配，符合既有分层。

## 2. 纯函数与去重
- `format_quote` / `build_quoted_prompt` 刻意做成**无副作用模块级纯函数**，便于单测与跨端复用；`SessionStore.quote_block` 委托 `format_quote`，不在多处重复拼装逻辑。
- `build_quoted_prompt` 对「无引用 / 无新问题 / 全空」三种边界分别兜底，返回可直接放进 `messages` 的 `content` 字符串，调用方无需再判空。

## 3. 类结构安全（规避历史坑）
- 上一版曾因把模块级函数误插到类中间，导致 `delete/append/messages` 游离出类。本轮新增类方法**集中插在 `get_summary` 与 `delete` 之间**，模块级纯函数**统一放文件末尾**。
- **AST 校验通过**：类方法数 33，`delete/append/messages/set_messages/touch/set_current` 均在类内，4 个模块级纯函数独立，`py_compile` 全绿。

## 4. 隐性 bug 预防：索引一致性
- 识别到 `_load_current_session()` 在会话首条非 `system` 时会在 `history` 前**补一条系统提示但不写回** `sessions.messages`，导致 `history` 下标相对 `messages` 偏移 1。
- 若直接拿 UI 下标去 `quote_block` / `branch_from`，会「选了第 2 条却引用/分支到第 3 条」。本轮在 `open_quote_picker` / `open_branch_picker` / `quote_last_reply` **操作前先 `_save_current_session()`** 建立一致基线（沿用 v11.3 `toggle_star_last` 已验证做法），彻底规避偏移。

## 5. 数据隔离与兼容
- `branch_from` 对每条消息**浅拷贝**（`dict(m)`），单测验证「改动分支消息不污染原会话」；`starred` 按 `<= index` 过滤，避免收藏引用到被截断消息；`tags` 继承、`summary` 清空。
- `branched_from={session_id,index}` 溯源 + `list_branches` 聚合，旧会话无该字段全部 `.get()` 读取，**向后兼容**（单测注入 legacy 会话验证）。
- 越界 / 负索引 / 会话不存在一律返回 `None`，与 `edit_message` / `toggle_star` 的返回约定一致。

## 6. 测试覆盖
- `test_v11_4_pc.py` **9/9**：引用格式化/过滤/截断/多行/多模态、组合提示各分支、越界、分支复制前缀/元数据/隔离/持久化/兼容。
- V11.3 回归 4/4、安卓 core 全量 `py_compile`、Qt offscreen 对话框渲染均通过；`core/sessions.py` 安卓副本同步无 Qt 依赖。

## 7. 版本号同步
- 11.3.0 → 11.4.0 在桌面/安卓 `config.py`/`mcp.py`/`pyproject.toml`（2 处）/selftest（4 处断言）四处同步，CLI `--version` 实跑一致，杜绝漂移。

**结论**：v11.4.0 架构延续既有分层，纯函数可测、类结构经 AST 校验、隐性索引偏移已预防、数据隔离与兼容完备，可维护性正向，建议发版。
