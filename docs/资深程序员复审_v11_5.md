# 资深程序员复审 · v11.5.0

**视角**：架构分层、依赖方向、算法取舍、状态与纯函数边界、可测试性。

## 1. 分层决策（本轮最值得肯定的一点）

`core/sessions.py` 已近 700 行，继续往里堆统计/对比会让它同时承担
「持久化 + 查询 + 分析」三种职责。本轮把分析能力拆到独立
**`core/insights.py`**：

```
core/insights.py   纯函数（diff / merge / stats / render）  ← 零依赖
        ↑ import
core/sessions.py   SessionStore.merge_into（薄状态层，只做落库 + current 切换）
```

关键点：**insights 不 import sessions**。若反向依赖会与
`SessionStore.merge_into → merge_messages` 形成环。本轮用「insights 自带
`message_content` 轻量文本提取（行为与 `sessions.message_text` 一致）」
来切断环，代价是一点重复、收益是依赖图无环、模块可独立单测。判断正确。

## 2. 算法取舍

- 对比没有上通用 LCS，而是 **最长共同前缀 + 同位置对齐**。理由：v11.4 的
  分支会话是「复制前缀后各自续写」，LCP 天然就是分叉点；LCS 反而会
  把后续偶然相同的短句错误对齐，结果难解释。
- `common_prefix_len` 被 `diff_sessions` 与 `merge_messages` **共用**，
  保证「对比看到的共同前缀」与「合并跳过的前缀」是同一套定义，不会漂移。
- `merge_messages` 返回 `mapping` 而非让上层自己猜下标，把「B 的第 j 条
  落在合并后第几条」这一易错计算收敛到一处，`merge_into` 据此重映射
  `starred`——这是纯函数与状态层协作的干净边界。

## 3. 历史坑的延续防御

- v11.3 曾因把 `build_summary_prompt` 插错位置导致 `delete/append` 等
  方法游离出类。本轮新增 `merge_into` 后**立刻用 AST 校验类归属**
  （34 个方法，`delete/append/messages` 仍在类内），习惯已固化。
- v11.3 曾因分发「陈旧构建」导致闪退。本轮 APK 脚本内置 **[3.5] 步骤**
  显式核验 gradle 工程里 `insights.py` / `sessions.py` / `config.py`
  已是 V11.5，从流程上杜绝复发。

## 4. 可测试性

22 项单测覆盖：共同前缀 / 完全一致 / 无关 / 空 / 多模态 / 截断、
merge 前缀 / 无关 / 显式前缀 / dedup 开关 / 无副作用、
stats 单会话 / 全局 / 空 / 多模态、token 估算、Markdown 渲染、
`merge_into` 收藏重映射 / tags / 非法 / 持久化、AST 零 GUI 依赖。
纯函数层零 Qt，测试 0.08s 跑完，不依赖显示器。

## 5. 改进建议（不阻塞发布）

| 建议 | 理由 |
|---|---|
| CI 加「桌面/安卓 core 字节一致」门禁 | 目前靠人工 `diff -q` |
| `estimate_tokens` 可选注入 tokenizer | 当前估算足够做统计，若将来要精算需替换点 |
| `diff_sessions` 可暴露 `ignore_system` 开关 | 对含不同 system 提示的会话对比更聚焦 |
| GUI exe 也随 tag 发布 | 当前仅 CLI exe 进 Release（ci.yml 只做 main/PR） |

**通过**。分层清晰、依赖无环、算法贴合领域语义、状态与纯函数边界干净，
并把历史两次事故的经验固化成了流程性防御。
