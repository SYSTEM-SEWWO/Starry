> 回应人：技术负责人（10 年后端/桌面端经验）
> 日期：2026-10-21
> 态度：HR 的 8 条意见整体质量很高，尤其是 P0 两条直指「玩具 vs 产品」的分界线。
> 原则：**能提升产品完成度的全盘接受；涉及架构风险的给出替代方案；损害核心体验的坚决不做。**

## 一、逐条响应

### P0-1 「关于」入口缺失 —— ✅ 完全接受，本轮落地

**技术判断**：完全同意。一个分发的桌面产品必须能自证身份（版本）、自愈（检查更新）、自助（快捷键/数据目录）、发声（反馈渠道）。

**实现方案**：
- 新增 `ui/about_dialog.py`：玻璃质感关于对话框，包含
  - 产品名「星语 · Starry」（见 P2-8）、版本号（读取 `core.config.APP_VERSION`）
  - 「检查更新」按钮：打开 GitHub Releases 页面（离线时给出提示，不做静默失败）
  - 快捷键速查表（Enter 发送 / Shift+Enter 换行 / Ctrl+Shift+S 截图 / 全局热键）
  - 「打开数据目录」按钮（配置、会话、日志所在位置，尊重用户知情权）
  - 反馈渠道：GitHub Issues 链接 + 托盘菜单入口
- 入口：标题栏「✦」logo 点击 + 托盘菜单「关于」+ 设置页按钮，三处可达。

### P0-2 用量统计 —— ✅ 完全接受，本轮落地

**技术判断**：同意，且这是所有商业化决策（配额、付费墙、团队看板）的地基。但要**克制**：
- 只做**本地统计**，绝不上传（隐私是本品类卖点，自毁长城的事不做）；
- 只统计聚合数字，不记录内容；
- token 数为**估算值**（按字符数 ÷ 1.6 近似中文字符比例），明确标注「估算」。

**实现方案**：
- 新增 `core/stats.py`：`UsageStats`，持久化于 `stats.json`，字段：
  `messages_sent / tool_calls / sessions_created / chars_sent / est_tokens / active_days / first_run / last_active`
- 埋点：`on_send`（消息+字符+估算 token）、`AgentWorker` 工具事件（tool_calls）、会话创建、每日活跃（UTC+8 日期去重）
- 展示：关于对话框「使用统计」区（只读），状态栏悬浮提示可看今日消息数。

### P1-3 代码插件安全加强 —— ✅ 完全接受，且比 HR 想得更进一步

**技术判断**：远程代码执行是本品类最大单点风险。HR 要求「安装前展示源码」是对的，但仅「展示」不够——**用户看不懂代码**。

**实现方案**（三道防线）：
1. **源码预览**：安装前对话框内嵌只读源码视图（等宽字体、限制高度可滚动），必须展开看完才能点确认；
2. **签名/来源提示**：明确显示插件来源（内置 / 远程索引 URL）、作者、版本；
3. **安装留痕**：已安装代码插件在市场中带「⚡ 已安装」标记与安装时间，卸载即注销全部工具（已有 `plugin_` 前缀隔离，保留）；
4. 沙箱维持现状（白名单模块 + 受限 `__builtins__`），但在关于/市场中明示「沙箱不是安全边界，请只安装可信来源」。

### P1-4 导出全部数据 —— ✅ 完全接受，本轮落地

**实现方案**：设置页「导出全部数据」→ 打包 `config.json + sessions.json + stats.json` 为一个 zip（含 README 说明各文件用途），文件对话框选保存位置。导入暂不做（会话合并语义复杂，v3.1 再议，避免半成品功能）。

### P1-5 热键状态可感知 —— ✅ 完全接受，本轮落地

**实现方案**：
- 设置页热钥输入框旁增加**状态标签**：`✓ 已生效` / `✗ 不可用（原因）` / `⏳ 未安装 pynput（pip install pynput）`；
- 启动时若不可用，托盘菜单不显示热键相关项，关于对话框的快捷键表中标注「未生效」；
- `core/hotkey.py` 已返回结构化 `(ok, msg)`，直接复用。

### P2-6 一键示例问题 —— ✅ 完全接受，本轮落地

**实现方案**：欢迎消息中给 3 个可点击示例问题（如「用一句话解释量子计算」「帮我 review 这段代码」「现在几点了？」），点击即发送。这同时解决了「空状态」与「首次成功对话」两个问题，成本极低。

### P2-7 失败重试/切换服务商 —— ⚠️ 部分接受，做一半

**技术判断**：错误气泡旁加「↻ 重试」完全合理（`AssistantBubble` 已有重新生成按钮，复用它即可，**零成本**）。但「切换服务商」快捷动作会把错误处理复杂化（设置对话框是模态的，错误态下弹出两层模态体验差），**本期不做**，改为：错误消息中直接提示「可点击右上角 ⚙ 切换服务商」，用文案引导替代交互。

### P2-8 品牌命名 —— ⚠️ 部分接受，控制改名面

**技术判断**：完全同意「AI 桌面助手」不像产品名。但全面重命名（窗口标题、代码、配置文件、文档）动静大、回归风险高，且用户已有认知。

**折中方案**：确立正式产品名 **「星语 · Starry」**（✦ 星标意象，与 UI 语言一致），用在：开屏副标题、关于对话框、托盘 tooltip、README 标题。窗口标题栏保留「AI 桌面助手」+ tooltip 展示全名。代码内部类名/模块名不改（无商业收益，纯风险）。

## 三、给 HR 的反馈（双向）

1. **P0-2 的统计建议非常好，但请补充「成功指标」**：建议明确北极星指标（如「周活跃会话中至少发生一次工具调用的比例」），否则统计容易沦为数字报表。
2. **P1-4 请确认合规边界**：「导出全部数据」包含 API Key，导出文件必须有明显警示（已在方案中），是否需要额外加密由业务侧定。
3. **商业模式第五节中「云端托管版」需要提前技术预研**：多用户 Key 托管涉及计费、限流、审计，与当前单机架构差异大，建议 v4 单独立项，不要挤占 v3.x 的体验打磨。
