# 资深程序员评审响应 · V10.0

> 以「架构合理性 / 技术债 / 可测试性 / 跨端一致性」视角评审 V10.0。

## 1. 架构评价

- **正确的分层**：把「平台检测」与「无界面引擎」拆成两个纯模块（`core/platforms.py`、
  `core/cli.py`），二者都不依赖 PyQt，从而让 CLI 二进制体积远小于 GUI 版。
- **复用优于重写**：`collect_chat`/`collect_agent` 直接驱动 `ChatClient` 与 `AgentRuntime`，
  没有为命令行另写一套伪流式逻辑——这是资深做法，避免双端行为分歧。
- **PyInstaller 双 spec 策略**：`starrystar.spec`（GUI）与 `starry_cli.spec`（console）分离，
  CLI 通过 `excludes` 主动剔除 PyQt5 全家桶，构建产物更干净。

## 2. 可测试性（亮点）

- `collect_chat/collect_agent` 为纯函数，自测用假 client 即可断言，不依赖网络/Qt。
- `run_cli(argv, out=)` 注入输出流，打印逻辑可断言（见 `test_v100_cli_platform`）。
- 平台检测用标准库，无副作用断言稳定。

## 3. 技术债与隐患

1. **`build_client` 重复了桌面版的 effort/provider 白名单**：`EFFORT_SUPPORTED_PROVIDERS`
   在 `core/cli.py` 与 `app/assistant.py` 各有一份。建议抽到 `core/config.py` 或 `core/api.py`
   作为单一事实源，避免日后新增服务商时两端遗漏。
2. **`--agent` 在 CLI 暴露本地工具执行**：与桌面版一致，但命令行场景更易被脚本化滥用，
   建议在 `execute_tool` 入口统一做破坏性操作确认（V7.5 已有雏形）。
3. **`--config` 外部路径**：当前仅 `json.load`，安全；但若未来支持 `exec` 式插件需警惕。

## 4. 改进建议（优先级）

- P1：抽取 `EFFORT_SUPPORTED_PROVIDERS` 到公共模块。
- P2：`--agent` 默认关闭或加 `--yes` 确认；新增 `--api-key-stdin`。
- P3：CLI 增加 `--history` 多轮会话（基于文件），对齐桌面端记忆连贯性。

## 5. 评分：**A**（分层清晰、可测试、复用得当；小技术债可控）
