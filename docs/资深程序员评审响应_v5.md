## P0-1 分发断链：源码 → 三平台一键打包

### 问题确认

HR 判断准确：v5.0 只交付源码，Windows 用户需要「装 Python → 装依赖 → 命令行启动」三连，实际转化率趋近于零。这是**交付形态缺陷**，不是功能缺陷。

### 实现

| 交付物 | 说明 |
|---|---|
| `starrystar.spec` | PyInstaller 单文件打包配置。关键点是 **hiddenimports 全量声明**：本项目对话框均为函数内懒加载（`from ui.prompt_dialog import PromptDialog`），PyInstaller 静态分析必然漏掉，已把 3 个 app 控制器 + 13 个 ui 对话框 + 17 个 core 子模块逐个显式登记 |
| `scripts/build_windows.ps1` | 建 venv → 装依赖 → 生成图标 → PyInstaller → 产出 `dist/星语Starry-Windows/星语Starry.exe` |
| `scripts/build_macos.sh` | 同上 + iconutil 转 icns + 自动给 spec 追加 BUNDLE 段产出 `.app` |
| `scripts/build_linux.sh` | 同上，产物为单文件可执行 + `chmod +x` |
| `scripts/make_icon.py` | 用 Pillow 现画品牌图标：翠绿垂直渐变圆角方底 + 白色四角星 ✦，输出 ico/png/1024png 三件套，**不需要设计师源文件也能出图** |
| `requirements-optional.txt` | 可选依赖独立清单（pyttsx3 / UPX 说明），主 requirements 保持最小 |

### 明确的工程决策（记录在案）

1. **单文件（onefile）而非目录**：目标用户是普通用户，双击一个 exe 比「拖文件夹」心智成本低一个量级；首次启动解压 10–30 秒的代价，用 README 说明覆盖。
2. **llama.cpp 不内嵌**：二进制约 100MB 且分平台，内嵌会让安装包膨胀 5 倍。产品内「模型库 → 运行时状态条」已有引导放置/下载的路径（`core/local_llm.py` 的 `find_llama_server` 会依次探测 PATH / 配置目录 / 常见位置）。**这是取舍，不是遗漏。**
3. **可选依赖不进主包**：pyttsx3 未安装时打包只告警不失败，运行期 `core/tts.py` 优雅降级——「装了多一个功能，不装少一个功能」，两条路都通。

### 验证

- spec 通过 Python AST 语法校验；三个构建脚本通过 `bash -n` / PowerShell 语法审查；
- 图标脚本实跑产出 `assets/icon.{png,ico}`（1024×1024 渐变 + ✦，目检通过）；
- **未在沙箱内执行完整 PyInstaller 构建**（沙箱无 Windows/macOS 目标平台，Linux onefile 构建需约 10 分钟且产物不可直接验证 GUI），构建链路在真实目标平台首次执行视为验收点——这一点已写入 README 的「已知限制」。

## P1-1 语音引擎黑盒：从「一句话提示」到「分平台自检」

### 实现

1. `core/tts.py` 新增 `tts_guidance()`：按 `sys.platform` 给出精确指引——
   - Windows：「已内置 SAPI5，无需额外配置」
   - macOS：「已内置语音合成，无需额外配置」
   - Linux：「还需 `sudo apt install espeak`，或 `pip install pyttsx3-espeak`」
2. 设置 → 外观页新增**「语音朗读」状态行**：实时显示「✓ 已就绪（离线合成，不联网、不上传文本）」或「✗ 未就绪 + 对应平台修复步骤」。
3. 运行期三处入口（气泡 🔊 / 托盘 / 命令面板）共用同一降级文案，**不存在「说得到做不到」的路径**。

### 验证

自测断言：`tts_guidance()` 非空；按平台分别断言包含 SAPI5 / macOS / espeak 关键词；设置页 `_update_tts_status()` 刷新后标签非空。沙箱内 pyttsx3 + espeak 真实可用，`Speaker.speak()` 完整跑通合成—播放—停止链路（见自测 21 节）。

## P2-1 分卷下载盲盒：下载前可见总体积

### 实现

`ui/models_dialog.py` 的 `ModelCard` 量化选择区新增 `quant_hint` 标签，随下拉选择实时刷新：

> ⚠ 该量化为 2 个分卷，需全部分片下载完成（共 4.0 GB）后 llama.cpp 才能加载

逻辑：选中项经 `ms.quant_parts()` 判定分卷数，跨分卷汇总 `size` 后格式化。单文件量化不显示提示（不制造噪音）。

### 验证

自测断言：2 分卷夹具提示含「2 个分卷」与汇总体积「2 KB」；单文件夹具提示为空字符串。Xvfb 截图确认（`screenshots/v5_fix_shard_hint.png`）。
