## 2. 本轮改动技术评估

### 安全性落地（S1–S4）— 质量高
- **EULA 防篡改令牌**：`sha256(EULA_TEXT + APP_VERSION)`，改动小、零依赖、
  可逆推但已诚实标注。✅
- **密钥离线校验**：`hashlib` 确定性校验位，签发/校验两端自洽、可单测。✅
- **配置 0o600**：posix 落盘即收敛权限，Windows 跳过（ACL 不同）。✅
- **MCP 命令校验**：`shutil.which` 前置，失败早返回；**明确无 shell 注入面**
  （列表式 Popen）。✅

### 依赖纪律 — 满分
v7.3→v7.5 三轮**零新第三方依赖**。MCP 用 `subprocess+json+threading` 自实现
stdio JSON-RPC，替代官方 SDK 的异步栈；密钥校验用 `hashlib`。这是资深
克制的体现，直接保住打包体积与可维护性。

### 可测试性 — 优秀
- 全量 **666 通过 / 0 失败**（较 v7.4 的 645 增 21 项，含真实起子进程、
  令牌防篡改、密钥校验、护栏端到端）。
- 纯函数（`tool_id`/`extract_text`/`validate_license_key`/`classify_destructive`）
  与 IO 分离，单测零副作用。
- `pyflakes` 对全部改动文件 exit=0。

## 4. 潜在技术债（提醒，非阻塞）

1. `McpManager.register_tools` 直接 mutate 全局 `core.agent.tools` 注册表——
   多实例/热重载时需确保 `unregister_all` 配对，否则工具泄漏。当前单例使用，安全。
2. `about_dialog` 密钥输入 `editingFinished` 即 `save()`，频繁保存；低频次
   可接受，高并发下建议防抖。
3. `_blur_pixmap` 的 Pillow↔QPixmap 内存 PNG 往返在每次重抓时发生，
   move 停稳防抖已缓解；超大屏可加尺寸上限。
