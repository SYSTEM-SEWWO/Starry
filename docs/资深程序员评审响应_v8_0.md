# 资深程序员评审响应 · v8.0

> 视角：资深程序员 / 架构。对 V8.0 实现做代码级审查，列出必办项、已闭环项与坦白项。

---

## 1. 架构评价（正面）

- **分层干净**：`core/memory.py` / `core/reasoning.py` 为**纯函数 + 无状态类**，零 UI 依赖，离线可单测；UI 仅在 `ui/memory_dialog.py` 与 `ui/chat_window.py` 做薄封装；`app/assistant.py` 做装配。符合「core → ui 单向依赖」既有约束。
- **零新依赖**：记忆 / 推理引擎仅用标准库（json/re/os/time），不增加安装体积与供应链风险。
- **测试驱动**：V8.0 新增 **34 项**自测（`selftest.py:3495 test_v80_memory_reasoning`），覆盖安全清洗 / 0o600 / 去重 / 检索 / 学习 / `<think>` 解析 / 流式分片，全绿。

## 2. 评审中发现的真实缺陷（已修复）

| 缺陷 | 现象 | 根因 | 修复 | 证据 |
| --- | --- | --- | --- | --- | --- |
| D1 状态跟踪 bug | `split_think_content` 对 `<think>想</think>答` 返回 `(答, 想)`（反转） | 在 for 循环内**先 append 再更新 `in_think`**，导致段归属错位 | 改为「先按当前态 append 段，再据开/闭标签更新 `in_think`」 | `core/reasoning.py:49` |
| D2 类型错误 | 真机对话后 `learn_from_conversation` 抛 `TypeError: expected string, got list` | `_on_finished` 取 `m.get("content")` 可能为**多部件列表**（带附件消息） | 改用 `message_text(m)` 强制字符串化 | `app/assistant.py:804` |
| D3 中文分词失效 | `relevant("我的职业是什么")` 返回 `[]` | 原正则 `[\w\u4e00-\u9fff]+` 把整句中文当**一个 token**，无法做词重叠 | 改为 `[a-zA-Z0-9_]+|[\u4e00-\u9fff]`（ASCII 词整体 + CJK 逐字） | `core/memory.py` `_WORD_RE` |

> 三处缺陷均在自测中暴露并修复，现已 727/0。这正是「先写测试再交付」的价值。

## 4. 坦白项（不粉饰）

- **真实 .exe 未在 Windows 真机跑**：本环境为 Linux，仅以 PyInstaller **同 spec 真实构建**（产出单文件 ELF）验证入口/隐藏导入/收集正确性；`starrystar.spec` 在 Windows 经 `scripts/build_windows.ps1` 即产出 `星语Starry.exe`，但 .exe 启动冒烟需在 Windows 真机补测（同 v7.6 路线）。
- **记忆为明文**：本地明文 + 0o600，未加密；多用户/上云场景需 v8.1 设备级加密。
- **许可仍客户端校验**：逆向可重算令牌（v7.7 服务端激活路线未变）。

## 5. 资深结论

V8.0 在**零新依赖、零架构债**前提下扩展了记忆与推理两大能力，测试覆盖率随功能同步增长。评审中暴露的 3 个真实 bug 已全部修复并有回归用例兜底。代码质量维持既有高水准。

**评级：A**（架构清爽、测试扎实、缺陷闭环透明）。
