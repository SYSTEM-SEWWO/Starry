# 项目结构与提交指南 · v12.0.0

> 目标：让这份交付「像 GitHub 提交项目和 GitHub Releases 一样好用」。

## 2. 三条硬约定

1. **`core/` 是唯一写入源**。`android/core/` 只能由 `scripts/sync_core.py` 生成。
   桌面专属模块（`attachment.py` / `hotkey.py` / `models.py` / `workers.py`）
   由 `DESKTOP_ONLY` 白名单排除，不要手动往 `android/core/` 里补文件。
2. **版本号只有 3 处声明**：`core/config.py::APP_VERSION`、
   `core/mcp.py::CLIENT_INFO["version"]`、`android/pyproject.toml::version`。
   改版本时三处一起改，CI 用 `--expect-version` 与 tag 比对，不一致直接红。
3. **一个版本一个文件夹**，命名 `星语Starry-vX.Y.Z`，由 `make_release.py` 生成。
   历史文件夹**只追加、不覆盖、不删除**；`RELEASES.md` 自动把旧版标为 `superseded`。

## 3. 本地准备与首次提交

> 当前工作目录经检查 **不是 git 仓库**（`git status` 返回
> `fatal: not a git repository`）。所有 workflow 与目录结构已备好，
> 但要触发 GitHub Actions 需先完成以下步骤。

```bash
cd 星语Starry

git init
git config user.name  "你的名字"
git config user.email "you@example.com"

# 建议先确认忽略规则覆盖构建产物与敏感文件
#   dist/  releases/*.zip  *.exe  *.deb  *.apk
#   config.json  .env  *.keystore  *.jks  *.p12  *.pfx  *.pem  *.key
#   __pycache__/  *.pyc  build/  .venv-cli/

git add .
git commit -m "feat: 星语 Starry v12.0.0（安卓闪退修复 / 三端同源 / 星尘卡 / 存档 / 发版体系）"

git remote add origin https://github.com/<你的账号>/<仓库名>.git
git branch -M main
git push -u origin main
```

## 4. 发版：一条 tag 走完全流程

```bash
# 发版前本地自检（建议全部跑一遍）
python scripts/sync_core.py --check
python scripts/check_core_parity.py --expect-version 12.0.0
python tests/test_v12_features.py
python tests/test_android_v12.py
python android/test_app_logic.py
QT_QPA_PLATFORM=offscreen python selftest.py

# 生成本地完整快照（可选，CI 也会生成）
python scripts/make_release.py --version 12.0.0

# 打 tag 触发三个 workflow
git tag -a v12.0.0 -m "v12.0.0"
git push origin v12.0.0
```

### CI 触发矩阵

| 工作流 | 触发 | 主要产物 |
| --- | --- | --- |
| `release.yml` | `push tags: v*.*.*` / `workflow_dispatch` | 完整 zip、`SHA256SUMS`、Release 正文、索引回写 |
| `build-android.yml` | `push tags: v*.*.*` | 签名 APK（过 `verify_apk.py --strict` 才发布） |
| `build-windows.yml` | `push tags: v*.*.*` | `星语Starry-CLI.exe`（自检通过后发布） |
| `ci.yml` | `push main` / PR | 常规测试 + GUI exe Artifact（14 天） |

三个 release 工作流共用 `concurrency: group: release-${{ github.ref }}` 串行执行，
一律 `append_body: true` 且不设 `name`，因此无论谁先创建 Release，
**APK / EXE / zip 最终都会落在同一个 Release 下**，互不覆盖。

## 5. 版本快照里有什么 / 没有什么

**有**：`main.py`、`starry_cli.py`、`selftest.py`、`requirements*.txt`、
两个 `.spec`、`启动.*`、`README.md`、`CHANGELOG.md`、`LICENSE`、
`SECURITY.md`、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、
`core/ ui/ app/ android/ assets/ scripts/ tests/ tools/ docs/ .github/` 整棵目录、
`RELEASE_NOTES.md`（本版发布说明）、`MANIFEST.md`（逐文件 SHA-256）、
`checksums.txt`、`assets/{apk,windows,linux}/` 二进制资产。

**没有**（白名单主动排除）：
`config.json`、`.env`、任意 `*.keystore / *.jks / *.p12 / *.pfx / *.pem / *.key`、
`*.bak`、`__pycache__`、`*.pyc`、`*.log`、`*.tmp`、
构建中间目录、`releases/` 目录本身、源码树内的 `*.exe / *.deb / *.apk / *.zip`。
`assert_no_secrets(dest)` 会在生成后二次扫描，命中即中止发版。

## 6. 常见问题

| 问题 | 处理 |
| --- | --- |
| `check_core_parity.py` 报版本不一致 | 检查 3 处版本声明；`--expect-version` 必须与 tag（去掉 `v`）完全一致 |
| `sync_core.py --check` 报漂移 | 跑 `python scripts/sync_core.py` 同步，然后 review diff 再提交；不要手改 `android/core/` |
| 推了 tag 但 Release 没出现 | 确认仓库已 `git init` 且 remote 正确；`git ls-remote --tags origin` 检查；看 Actions 的 `verify` job 是否红 |
| `selftest.py` 报网关统计 / 预算失败 | v12.0 已修复：`selftest.py` 顶部自动注入独立 `STARRY_DATA_DIR`，各网关测试段再各自隔离，直接跑即为 **779/0**。早期「改 `HOME` / `APPDATA` 隔离」在 Windows 上无效（真实路径读 `USERPROFILE`），请勿再沿用 |
| EXE 控制台中文乱码 | Windows 非 UTF-8 代码页的显示限制；`starry_cli.py` 已做 `reconfigure(errors="replace")`，不影响功能与退出码 |
| 想要免 Python 依赖的 Linux ELF 版 deb | 本机无法交叉编译 ELF；由 CI 的 ubuntu job 产出，本机 deb 为「源码 + `python3` 启动器」形态 |
| 发布后发现私钥被打包 | `assert_no_secrets` 会在生成阶段拦下；若来自历史 v11.5 快照，请勿公开该 zip 并轮换密钥 |
