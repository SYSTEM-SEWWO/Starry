## 2. 首次提交到 GitHub

> 当前工作目录**不是 git 仓库**（实测 `fatal: not a git repository`）。
> workflow 已备好，但必须完成以下步骤才会触发。

```bash
git init
git add .
git commit -m "feat: 星语 Starry v13.0.0 电脑端大版本"
git branch -M main
git remote add origin https://github.com/<owner>/<repo>.git
git push -u origin main
```

**提交前务必检查**：

```bash
# 1) 版本与三端同源门禁
python scripts/check_core_parity.py --expect-version 13.0.0

# 2) 全量回归
QT_QPA_PLATFORM=offscreen python selftest.py
python tests/test_v12_features.py
python tests/test_v13_features.py
python tests/test_android_v12.py
python android/test_app_logic.py

# 3) 确认没有把密钥 / 配置提交进去
#    make_release.py 的 assert_no_secrets() 只保护快照，不保护 git 仓库本身
git status --short
```

> 建议在 `.gitignore` 中排除 `dist/`、`_build_tmp/`、`.starry-data/`、`config.json`、
> `*.keystore`、`*.jks`、`*.p12`、`*.pfx`、`.env`。
> **历史 v11.5 快照含 `starry-release.keystore`，公开分发前必须轮换或设为私有。**

## 3. 打 tag 发版

```bash
git tag -a v13.0.0 -m "v13.0.0 整体项目 / 多线并行 / 自动更新"
git push origin v13.0.0
```

会触发（同一 `concurrency: release-${{ github.ref }}` 串行化）：

| 顺序 | workflow | 产出 |
| --- | --- | --- |
| 1 | `release.yml` | 版本门禁 + 全量自测 → 完整快照 + zip + 校验和 → 创建 GitHub Release |
| 2 | `build-windows.yml` | 追加 CLI EXE 到 Release |
| 3 | `build-android.yml` | 追加签名 APK 到 Release（需 Android 工具链） |
| 4 | `update-manifest.yml` | Release published 后下载全部资产 → 生成权威 `update.json` → 覆盖上传 |

`update-manifest.yml` 支持 `workflow_dispatch` 指定 tag，
**APK 晚到时重跑一次即可补齐 android 条目**。

## 4. 本地生成版本快照

```bash
# 先确保资产目录齐备
python scripts/gen_update_manifest.py --version 13.0.0

# 生成完整自包含文件夹 + zip
python scripts/make_release.py --version 13.0.0 \
    --summary "v13.0.0 大版本更新（整体项目 / 多线并行 / 自动更新）"
```

产出：

- `releases/星语Starry-v13.0.0/`：全部源码 + 主文件 + 全部 `docs/*.md` +
  构建脚本 + `.github/` + `assets/` + `MANIFEST.md` + `checksums.txt` + `RELEASE_NOTES.md`
- 同名 `.zip`
- `releases/SHA256SUMS-v13.0.0.txt`
- 自动更新 `releases/RELEASES.md`（幂等，历史版本自动补录、按版本倒序）

安全门禁：`EXCLUDE_PATTERNS` 通配排除密钥/证书/`config.json`/`.env`/`*.bak`，
`assert_no_secrets(dest)` 在发布前扫描，发现泄漏直接中止发版。

## 5. 改动 core 后的必跑链

```bash
python scripts/sync_core.py                                  # 同步到 android/core
python scripts/check_core_parity.py --expect-version 13.0.0 # 字节一致 + AST
python tests/test_v13_features.py                           # 172 项
# 若改了 CLI / spec，重建产物
python -m PyInstaller starry_cli.spec --noconfirm --clean
python scripts/build_deb.py
python scripts/gen_update_manifest.py --version 13.0.0
```

**版本升级时**只改三处单一真源：`core/config.py::APP_VERSION`、
`core/mcp.py::CLIENT_INFO`、`android/pyproject.toml`（2 处 version），
然后 `sync_core.py` 会把 `config.py` / `mcp.py` 同步到 `android/core/`。
测试里的版本断言已改为动态读取，不需要跟着改。

## 6. 常见问题

| 问题 | 处理 |
| --- | --- |
| `fatal: not a git repository` | 按 §2 初始化 |
| workflow 没触发 | 确认 tag 形如 `v*.*.*`、已 push tag、Actions 已启用、`permissions: contents: write` |
| `check_core_parity` 报版本不一致 | 三处真源 + `scripts/build_deb.py::VERSION` 一起核对 |
| Release 里缺 `update.json` | 手动 dispatch `update-manifest.yml` 指定 tag |
| `update.json` 缺 android 条目 | APK 尚未上传；上传后重跑该 workflow |
| selftest 报失败 | 用 `STARRY_DATA_DIR` 隔离网关数据；**不要只设 `HOME`**（Windows 读 `USERPROFILE`） |
| 快照里出现密钥 | `assert_no_secrets()` 会中止发版；检查 `EXCLUDE_PATTERNS` 与 `.gitignore` |
