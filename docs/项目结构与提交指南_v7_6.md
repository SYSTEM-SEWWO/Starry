## 3. 本地提交流程

```bash
# 1) 跑自测（必须 0 失败）
QT_QPA_PLATFORM=offscreen python selftest.py

# 2) 提交（沿用 feat: vX.Y.Z —— … 约定）
git add -A
git commit -m "feat: v7.6.0 —— 提交结构补全 / exe 打包验证 / API 开放文档"

# 3) 推送 & 开 PR（填 .github/PULL_REQUEST_TEMPLATE.md）
git push origin <branch>
```

> ⚠️ 切勿 `git add config.json` 或含 API Key 的任意文件；`.gitignore` 已兜底忽略，但人工 `git add -f` 会绕过它。

## 4. 打包成 .exe（三平台）

```bash
# Windows（产出 星语Starry.exe）
powershell -File scripts/build_windows.ps1

# Linux（产出 星语Starry）
bash scripts/build_linux.sh

# macOS（产出 .app）
bash scripts/build_macos.sh
```

- 打包配置见 [`starrystar.spec`](../starrystar.spec)：`Analysis(["main.py"], hiddenimports=_HIDDEN, excludes=重量级Qt模块)` → `EXE(..., console=False, icon="assets/icon.ico")`。
- `hiddenimports` 已显式声明全部懒加载模块（`ui.frost`、`ui.eula_dialog`、`core.mcp`、`core.screen` 等），避免 PyInstaller 静态分析遗漏。
- **本次验证**：在 Linux 上执行 `pyinstaller starrystar.spec` 成功产出 134MB 单文件可执行（`file` 识别为 ELF），证明入口、`hiddenimports`、PyQt5 收集、单文件装配全部正确；同一 spec 在 Windows 下即产出 `星语Starry.exe`。
- 浏览器内核（chromium ~150MB）与本地模型二进制**刻意不内嵌**，由产品内「设置」页按需安装，控制安装包体积。

## 5. 最小可运行依赖

| 依赖 | 用途 | 是否必需 |
| --- | --- | --- |
| PyQt5 | GUI | 必需 |
| requests | 模型 API 调用 | 必需 |
| markdown | 回复渲染 | 必需 |
| beautifulsoup4 | 网页接入解析 | 必需 |
| pypdf | PDF 附件解析 | 可选 |
| pynput | 全局热键 | 可选 |
| pyttsx3 / playwright | TTS / 网页版接入 | 可选（缺失不致命） |

新增依赖须先在 Issue 论证，再写入对应 `requirements*.txt` 并同步 `starrystar.spec::excludes`（如有冲突模块）。
