# 项目结构与提交指南 · 星语 Starry V9.0

> 面向协作者 / 提交者的结构说明。每版产出独立「版本化文件夹」，确保打包出来是完整工程。

## 1. 顶层结构（主线 `ai-assistant/`）

```
ai-assistant/
├── main.py                 # 入口（EULA 闸门 + 启动）
├── selftest.py             # 无头自测（QT_QPA_PLATFORM=offscreen，751 项）
├── starrystar.spec         # PyInstaller 单文件打包（隐藏导入含 core.rea）
├── core/                   # 业务逻辑：config / api / mcp / memory / reasoning / rea …
├── ui/                     # PyQt5 界面：floating_ball / chat_window / settings_dialog …
├── app/                    # 控制器：assistant / model_controller / screenshot_controller
├── docs/                   # 全部评审 / API / 调研文档（*_v9_0.md 等）
├── README.md / CHANGELOG.md / LICENSE / SECURITY.md
└── CONTRIBUTING.md / CODE_OF_CONDUCT.md
```

## 2. 版本化文件夹（用户明确要求）

每次更新版本，须把**完整工程**放入一个以版本号后缀的文件夹：

```
星语Starry-v9.0/    ← 当前完整工程（源码 + 全部 docs/*.md + main.py + README/CHANGELOG）
星语Starry-v8.0/    ← 上一版基线（同样完整）
```

要求：
- 每个文件夹**自包含**：含全部源码、全部 `docs/*.md`、主文件 `main.py`、README/CHANGELOG；
- 各自压缩为 `星语Starry-vX.Y.zip`，便于分发与对比；
- 版本号四处一致：`core/config.py::APP_VERSION`、`core/mcp.py::CLIENT_INFO`、`selftest.py` 断言、文档标题。

生成方式（示例）：
```bash
# 当前树（排除 .git/缓存/构建产物）
tar cf - --exclude='.git' --exclude='__pycache__' --exclude='*.pyc' \
        --exclude='dist' --exclude='build' . \
  | (mkdir -p 星语Starry-v9.0 && tar xf - -C 星语Starry-v9.0)
zip -rq 星语Starry-v9.0.zip 星语Starry-v9.0
# 历史版本用 git archive
git archive --format=tar <commit> | (mkdir -p 星语Starry-v8.0 && tar xf - -C 星语Starry-v8.0)
```

## 3. 提交前检查清单

1. 版本号四处改齐（config / mcp / selftest / 文档）；
2. `QT_QPA_PLATFORM=offscreen python3 selftest.py` 全绿（当前 751）；
3. `starrystar.spec` 隐藏导入含新增模块（本次 `core.rea`）；
4. `.gitignore` 忽略敏感运行数据；
5. 八份评审/API/调研文档齐备（`docs/*_v9_0.md`）；
6. PyInstaller 真实构建验证（或同 spec 在目标平台构建）；
7. 生成版本化文件夹 + zip。

